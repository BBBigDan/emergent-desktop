# emergent-agent · 协议 + 真模型 + 真集群

```
node agent/server.mjs                    # 读 agent/.env，默认硅基流动 + 直连 Olares
MODEL=mock node agent/server.mjs         # 不联网，用假模型跑协议
SYS=mock node agent/server.mjs           # 工具返回固定假数据（截图 / 自测要可复现）
SYS=host node agent/server.mjs           # 退回读本机 /proc（没有集群凭据时自动退回）
```

零依赖，只用 Node 内建模块。**模型是真的，数据也是真的**：`sys_status` 读的是那台
Olares 的 Prometheus，`app_list` 读的是它的 k8s API，`logs_tail` 读的是它的容器日志。

**agent 不是页面，是桌面的一层。** 根路径 `/` 给的是桌面壳，agent 由
`shell/src/deskagent.js` 挂在桌面自己的粒子场上：鼠标贴到底边、或双击桌面空白唤出，
场就地展开（同一批粒子从环境形态凝成界面），Esc 收起、散回球面。
`shell/agent.html` 还留着，但它只是"把场单独拿出来看"的调试页（`?dev=1` 才显示观察窗）。

这一版证明的是那条链路：模型发工具调用 → 工具执行 → 场景指令下发 → 手势意图回灌 → 审批挂起。
换数据源只改 `sources/`，协议一个字都不用动。

## 三个文件分掉了三件事

| 文件 | 管什么 | 换它意味着 |
|---|---|---|
| `model.openai.mjs` | 怎么跟模型说话（OpenAI 兼容） | 换厂商 / 换模型 |
| `prompt.mjs` | 模型知道什么（场语法、说话纪律、手势语义） | 调"它怎么想" |
| `scene.schema.mjs` | 模型**不许**做什么（白名单、截断、clamp） | 调"它最多能干什么" |

第三件是最容易被忽略的：接上真模型之后，`spec` 就不再是"我写的对象"，而是**外部输入**。
没有这一层，模型把 `value` 写成 71 会被 `clamp` 成 1 —— 仪表显示满格，
界面上看不出是谁的错，只会觉得这系统不准。所以校验层做两件事：**挡住**，然后**如实回报**
（`dropped` / `adjusted` 作为工具结果回给模型，否则它会在同一个错误上重复八次）。

## 长期记忆（M2）

`memory.mjs`（抽取 / 回忆 / 巩固）+ 一个**图存储**。它做三件事：

1. **抽取**：一轮问答结束后，让主模型把"值得长期记住"的东西写成 1~3 条事实
   （偏好 / 做过的事 / 因果 / 认得的东西）；读数、寒暄、计划都不记。
2. **回忆**：下一轮开头按用户这句话去图里定向取几条，拼进系统提示。
   不是 dump 全库 —— 7B 的窗口撑不住，而且它会开始复述过去。
3. **巩固**：每 6 轮（或 6 小时）算一次五信号，剪掉没人再碰的，把反复同框的实体
   塌缩成摘要节点，拍一张快照。

存储有两份实现，**方法完全一样**（上层不知道下面是谁）：

| 实现 | 用在哪 | 是什么 |
|---|---|---|
| `sources/graph.axolotl.mjs` | 集群（默认） | HTTP 调侧车 `memsvc/server.py` → Rust 图引擎 axolotl，`.axeb` |
| `sources/graph.mjs` | 本地开发 / 自测 | `node:sqlite`，零依赖备胎 |

```
MEMORY_STORE=axolotl   # 集群默认；侧车不在就**停用记忆**，不退回 SQLite（防记忆分叉）
MEMORY_STORE=sqlite    # 本地跑：node agent/server.mjs（没有 Linux wheel 也能测逻辑）
MEMORY_STORE=auto      # 先试侧车，失败退回 SQLite（默认值）
```

| 位置 | 内容 |
|---|---|
| `~/Agent/memory/memory.axeb` | 图：fact / entity / community 三类节点 + `about` 边（axolotl 二进制） |
| `~/Agent/memory/memory.db` | SQLite 版（迁移后改名 `.migrated`） |
| `~/Agent/memory/snapshots/` | 快照，留最近 5 份 |
| `GET /agent/api/memory?q=n8n` | 当前 stats + 一次回忆 —— **唯一可观测入口** |
| `GET /agent/api/memory?sweep=1` | 顺手做一次巩固（剪枝 / 社群合并 / 快照），返回报告 |

环境变量：`MEMORY=0` 关掉；`MEMORY_DIR=/path` 指定目录；`MEMORY_URL` 侧车地址（默认
`http://127.0.0.1:7801`）。

工具：`memory_recall`（查）/ `memory_stats`（看有什么）/ `memory_forget`（忘，danger 过审批）。
抽取失败只丢那一轮；侧车不可用时记忆停用，桌面照常（**不会**偷偷退回 SQLite）。

自测（不需要模型、不需要集群、不需要侧车）：

```
node agent/memory.test.mjs        # 用 SQLite 那份跑全部逻辑
```

侧车的接口、wheel 怎么重建、怎么排障：见 `deploy/README.md` 的"记忆侧车（axolotl）"。

## 人格层（M5，`persona.mjs`）

记忆回答的是"用户说过什么"；人格层回答的是**"它自己经历过什么"**。两件事，
两条通道，不能混：

| | 记忆（M2） | 人格（M5） |
|---|---|---|
| 内容 | 用户说的、偏好、因果 | 它自己动了手造成的后果，加上以前落地的旧事 |
| 触发 | 与用户这句话**相关**才取 | 与当前问题**正交**才说（相关了就该走记忆） |
| 失败的样子 | 答不上以前的事 | 答非所问（问磁盘，它说"我上周挪过文件"） |

### 种子只有两个来源，都不是模型自己说的

1. **动作后果**：`k8s_restart` / `fs_move` / `fs_delete` / `fs_write` / `mem_trim` /
   `tool_keep` / `skill_save` 成功执行之后，翻成一句人话（"重启了 n8n"）落进
   `~/Agent/memory/drift/YYYY-MM.jsonl`。读数类的（`sys_status`、`fs_scan`、`logs_tail`）
   **一律不收** —— 每轮都有，收进来会把真事淹掉，而且"我看了一眼内存"不算经历。
2. **记忆库里的旧事实**：`memory.recent()`，现取不复制（复制一份必然和图库漂移）。

模型自己说过的话永远不进种子：它上一轮编一句，这一轮就当成自己的经历 —— 那是最快的一种自我污染。

两条形状检查挡在入口：**读数**（带百分比且没有"会持续下去"的动作词，比如
"n8n 占用 60% 内存"）和**抽取残渣**（"我做了 → 工具返回"——实测 7B 会把这种旁白
当事实交上来，长度检查全都过）。同一张动作词表在 `memory.mjs` 里也用一份，
两边不一致的后果是"记忆里收进来、人格里又说出去"。

### 注入：正交 + 泄漏率 + 复用期

- **正交（Ω ⟂ goal）**：种子里只要有一个实义二元组出现在用户这句话里，就不注入 ——
  那时候该走记忆通道。判据是字面重合，**同义词和中外混写跨不过去**（"挪到了 Documents"
  和"我的文件都在哪"字面上没有共同词）。这条已知局限靠下面两条兜。
- **泄漏率**（`PERSONA_LEAK`，默认 0.35）：每轮有 35% 的机会说点旧事。1 = 祥林嫂，
  0 = 没这个功能。面板上显示实际比率，恒等 0 就说明"接是接了，但一次都没说过"。
- **复用期 7 天**：同一条不反复说。
- **例外**：用户直接问"你最近干了什么"，上面三条全让路（必答、不判正交、不受复用期限制）。
  实测踩过：问这句时两条种子都因"刚说过"被挡，它答了句"我看一眼"。

注入上限 2 条（自我指涉时 3 条），每条 ≤42 字。

### 编号不给模型

验收要求"它说的那句话能指出是哪来的"。**第一版让模型自己写编号，失败了两次**：

- 照抄提示词里的示例，写出一个查不到的 `#41`；
- 编号写对了，但张冠李戴（`#3` 是"挪文件"，它说成"我查过内存"）。

所以编号改由系统给：模型只管把事说成人话；它说完之后服务端用 `traceRefs()`
核一遍这句话的词，认出说了哪几条，编号随 `say.refs` 和面板下发。
判据是"至少一个**中文**二元组对上"—— 只共享实体名（n8n）不算，实测那种情况
它说的完全是另一件事。

### 看它在想什么

```
GET /agent/api/persona           # 种子数 / 注入次数 / 实际泄漏率 / 最近 6 次注入
GET /agent/api/persona?all=1     # 加上种子明细与注入明细（可核对到 sid / turn / 工具名）
?dev=1                           # 观察窗里 persona 行：注入的 #N，以及"它提到了 #N"
```

`persona.md`（人可读可改）是它的自我设定，第一次启动时写一份默认的，改了下一轮生效。

```
PERSONA=off                      # 总开关。这是风味层，不是核心层 —— 关掉之后记忆照常
PERSONA_LEAK=0.5                 # 换手感
PERSONA_DIR=/path                # 落盘位置（默认 ~/Agent/memory）
```

自测：`node agent/persona.test.mjs`（60 项：正交判据、动作翻译、种子采集与去重、
注入的三条限制、落盘回读、总开关、溯源判据）。

## 自造工具（M4）

不可能给每个应用写适配器。所以给它一套"读文档 → 写脚本 → 试跑 → 装起来"的流程，
产物是**用户能在 Files 里打开、改、删的普通文件**：

```
~/Agent/tools/<name>/manifest.json    叫什么、要什么参数、要碰什么（needs）、版本
~/Agent/tools/<name>/run.mjs|run.cjs  脚本，只用 node 内建模块
~/Agent/tools/<name>/history/         旧版本（改了代码就归档，可回滚）
~/Agent/skills/<slug>.md              "该怎么做"，会进系统提示
~/Agent/audit/tools-<day>.jsonl       每次调用一行：谁、什么参数、多久、成没成
```

| 工具 | 干什么 |
|---|---|
| `web_get` | 读一个 http 文档（造工具之前先看） |
| `tool_write` | 起个头：名字 / 说明 / 参数表 / net + fs（都可以不填），**落成草稿** |
| `tool_code` | 单独贴脚本（只有 name + code 两个字段） |
| `tool_try` | 试跑一次（danger，过审批；审批前系统会把代码铺到屏幕上） |
| `tool_keep` | 注册，之后每轮工具表里都有它（danger） |
| `tool_list` | 已装的 + 草稿 |
| `skill_save` | 记一页"以后就这么办" |

**三处不由模型决定的地方，也是这层的全部价值：**

1. **草稿不是工具。** `tool_write` 只落盘（`manifest.json` 里 `status: draft`），
   下一轮的工具表里没有它。只有 `tool_keep`（用户点过头）之后才注册。
   改一个已发布的工具，状态自动退回 draft —— 改了代码就得重新看一眼。
2. **域名清单由运行时强制，而且它有两个来源**（`agent/tools/guard.mjs`，靠
   `node --import` 先于脚本执行）。生效的清单 = `manifest.needs.net` ∪ **从代码里读出来的
   完整 URL**（只对 `level: confirm` 生效）。两个来源都会摆到审批卡上：卡片上写的是
   "这一次真的能连哪些"，不是"模型说它能连哪些"。
   **读不出来的地址一律拒** —— 拼出来的域名（`['evil','example','org'].join('.')`）
   不会出现在卡片上，也就进不来。这是护栏真正挡的东西：不是"它想连什么"，
   而是"卡片没说的那一部分"。
   文件：`fs` 三套 API（同步 / 回调 / promises）全部包住，路径不在 `needs.fs` 里直接抛，
   `rename(from,to)` 两个参数都要过。进程：`child_process` / `process.binding` /
   `process.dlopen` 一律禁。子进程环境只给 `PATH / HOME / TZ / EM_TOOL_ARGS / EM_TOOL_NEEDS` ——
   给全了等于把集群令牌一起递过去。
   `tool_keep` 时会把读出来的域名落进 `manifest.needs.net`，之后再跑就不用推断了；
   用户翻 `~/Agent/tools` 也能看到它要连哪儿。
3. **每次调用进审计。** 自造工具是这台机器上唯一"行为不预先确定"的东西。

它不是沙箱。同一进程里的 JS 总能绕（`process.mainModule` 之类），
它把"偷偷连一个域名"从一行 `fetch` 变成"对着要给人看的 manifest 撒谎"。
这是**知情**级别的防护，真隔离得上容器，那是另一件事。

**为什么代码要单独发**（`tool_code` 而不是 `tool_write` 一把梭）：
实测 7B 让它在一个 JSON 里同时写 `params` 和三十行脚本，它会**静默地**只发
`name/description/params`，`code` 根本不在参数里 —— 然后重试十次都一样，
屏幕上只看到"少了必填参数 code"。拆成"元数据"和"代码"两步之后，
最难的那一步只剩一个字符串字段。

自测（不需要模型、不需要集群）：

```
node agent/tools/forge.test.mjs   # 31 项：拼出来的域名被拒、越权文件被拒、代码里读得到的放行、
                                  # 超时被杀、版本与审计、忘填参数时兜底、扁平 needs 与继承
```

（Pod 里也能跑：`kubectl exec … -c agent -- sh -c 'cd /app && node agent/tools/forge.test.mjs'`，
顺便验证 Linux 上的路径守卫。）

## 数据从哪来（`sources/k8s.mjs`）

不调 `kubectl`，直接用 `node:https` 打 k8s API。三个理由：零依赖（kubectl 是 60MB 二进制，
而这个仓库的约定是部署时什么都不用装）、一条链路够用（API 的 service proxy 让我们用一个
HTTPS 端点就能访问集群内任何 Service，Prometheus 就是靠它）、同一份代码在两种部署下都能跑。

| 要什么 | 从哪读 |
|---|---|
| 此刻的 CPU / 内存 / 磁盘 | Prometheus 瞬时查询（node-exporter 的 15s 采样） |
| 这一小时的走势 | Prometheus `query_range`（60 点） |
| 谁在吃内存 | `container_memory_working_set_bytes`（**不是** `kubectl top` —— 这个集群没装 metrics-server，实测 `top` 直接报 "Metrics API not available"） |
| 应用是什么状态 | k8s API 的 deployment / pod 对象（Prometheus 不知道"应用"这个概念） |
| 日志 | `.../pods/<pod>/log?container=<c>`，先滤掉 linkerd-proxy 这类 sidecar |

**凭据**按"越靠内越优先"找：in-cluster 的 serviceaccount → `KUBECONFIG` / `agent/.kube/config`。
k3s 写的 kubeconfig 里 `server` 是 `127.0.0.1:6443`（那是集群内视角），从外面用时
用 `KUBE_SERVER=https://<公网IP>:6443` 覆盖。

> `agent/.kube/` 已在 `.gitignore` 里。那里面是**客户端私钥**，
> 推上去等于把整台机器的 root shell 交出去。

### 硅基流动的实测记录（2026-10-21）

- 接口通，key 有效，`/v1/models` 能列出 98 个模型。
- **但所有模型都返回 `402 code 30001 account balance insufficient`** —— 包括标着"免费"的那些。
- **这条是怎么来的（重要，别再踩）**：账户余额本来是 0（或赠金已过期），
  ¥0 的模型还能跑；探测时混进了四个收费模型（`DeepSeek-V4-Flash`、`GLM-5.3-Flash`、
  `Qwen3.5-9B` 等），每个只跑了几百 token、合计不到一分钱 —— 但余额是 0，
  扣费异步结算后变成负数，触发「现金余额 < 0 → 停止该账户的全部 API」，
  **于是几分钟后连 ¥0 的 Qwen 也开始 402**。
  名字里带 `Flash` 不代表免费，这是这次最贵的一课。
- 解锁办法：实名认证 + 充值任意金额（0.01 元即可），之后扣费顺序变成「现金 → 券」。
- 当时的处置：默认 `MODEL` 改成 `Qwen/Qwen2.5-7B-Instruct`（¥0），并在
  `tools/dev/probe-model.mjs` 里做了硬保护：探到非免费名单的模型会直接拒绝，
  必须显式 `--paid`。
- **2026-10-23 又换了**（充过值、余额正常）：默认改成
  `deepseek-ai/DeepSeek-V4.1-Flash`，因为它会思考。硬保护保留 —— 它挡的是
  "随手试探就把账户打停"，和用哪个模型无关。

能用的时候实测延迟（带工具调用）：`Qwen2.5-7B-Instruct` ~0.9s/步最稳；
`DeepSeek-V4-Flash` ~1.1s/步且会并行发调用（收费）；`GLM-5.3-Flash` ~3s/步（收费）；
`Qwen3-8B` 首次调用 90s（冷启动）。

### 换模型这件事：为什么要一个"会思考"的（2026-10-23）

界面左上那块「思考过程」里的 `[想]` 行，唯一的真实来源是模型的 `reasoning_content`。
**不会思考的模型，那栏里就只有"调了什么、画了什么"** —— 用户的原话是"感觉很奇怪"。
所以默认从 `Qwen/Qwen2.5-7B-Instruct` 换成了 `deepseek-ai/DeepSeek-V4.1-Flash`。

免费名单里**确实有能思考的**，实测（另写了一个探针，因为这个判据不是"能不能跑"）：

| 模型 | 免费 | 思考 | 工具调用 | 一轮耗时 |
|---|---|---|---|---|
| `Qwen/Qwen2.5-7B-Instruct` | ✅ | **无**（没有 reasoning_content） | 稳 | 0.4~1s |
| `Qwen/Qwen3-8B` | ✅ | 332 字 | 正常（sys_status → scene_show） | 8.5s / 9s |
| `THUDM/GLM-Z1-9B-0414` | ✅ | 239 字，带 `<think>` 标签 | 正常 | 2.7s / **回灌 12s** |
| `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B` | ✅ | 有 | **不支持 function call**（400） | — |
| `Qwen/Qwen3.5-4B` | ✅ | 有 | 把调用写成 `<tool_call>` 文本，废 | — |
| `XingChenAGI/Xing4.0-29B` | ✅ | 45 字 | 会重复调同一个工具 | 0.8s |
| `THUDM/GLM-4-9B-0414` | ✅ | **无** | 一次到位（`sys_status{}`） | 0.5s |
| `Qwen/Qwen3.5-9B` | ✅ | 60 字（中文） | 正常 | 4.4s |

结论：能思考且会调工具的只有 **Qwen3-8B** 和 **GLM-Z1-9B**，都慢 3~10 倍，
且单轮思考上千字。省钱的切法是 `MODEL=Qwen/Qwen3-8B`，适配器一行都不用改。

**思考的语言要专门要求。** 不写这句，V4.1-Flash 的 `reasoning_content` 全是英文
（"Need to report. Maybe also scene_show?…"）。三种说法只有一种有效：

| 写法 | 效果 |
|---|---|
| `**思考也用中文。**` | ✅ 23 字里 21 个汉字 |
| `请全程用简体中文思考和回答。` | ❌ 全英文 |
| `Think in Simplified Chinese.` | ❌ 全英文（反而更坚定） |

`prompt.mjs` 里那行的措辞是试出来的，不要"优化"。

**英文思考照样显示，一句都不丢。** 曾经在这里筛过"中文占比 < 30% 就丢整句"，
理由写的是"英文夹在中文界面里比空着更像界面坏了" —— 这是**为了界面上的一致性
去删真实信息**，被用户明确否掉了（"有些模型的底层是有英文逻辑的，你这样会导致
用户看到的信息出现缺失"）。而且丢掉的那几句往往正是推理链：越复杂的事，模型越容易
切回母语。让思考说中文是提示词的事（上面那句），不是出口的事；它不听，屏幕上就照实
显示英文。`fitSent()` 因此改成按**显示宽度**收口（汉字 1、ASCII 0.55），
否则同样一句意思英文只剩三个词。

### 换模型：界面上点一下（`models.mjs` + `/api/models`）

以前换模型只能改 `.env` 重启 —— 用户能看见名字，但改不了它。现在**名字本身就是按钮**：
点开是一块玻璃表（`shell/src/modelpick.js`），分「本地 / 平台」两组，每行给四件事：
会不会想、会不会调工具、多少钱、走哪个接口。

三件事值得记下来，因为它们都是"看起来能用、其实不能用"的来源：

1. **不会调工具的模型留在表里，但灰着。** `DeepSeek-R1-0528-Qwen3-8B`（接口 400）和
   `Qwen3.5-4B`（把调用写成文本）都在表里，写明原因、点不动。删掉它们的话，
   用户听说"R1 免费又能想"只会觉得这张表漏了东西。
2. **单价不知道就写 `未定价`，不写 0。** 表里只有"确认 ¥0"的才敢标 `¥0`；
   收费但没有单价的（就是默认那个 V4.1-Flash）显示「未定价」。这条在 `usage.mjs`
   也有一条一样的规矩，现在两处**共用同一个 `priceOf()`**（以前各存一份，
   列表说免费、账上扣钱这种错没人能自己发现）。
3. **本地那一组是运行时探测的**：问 Ollama `/api/tags` 要清单、`/api/show` 要
   `capabilities`。老版本 Ollama 不报能力清单，那两格就写 `?` —— **不按名字猜**
   （猜错的表现是"标着会想，那栏里一个字都没有"）。没装 Ollama 就很正常地只剩 `mock`。

切换本身走 `POST /api/send {t:'model', id}`，服务端 `switchModel()` 管四件事：
跑着的时候拒绝（一轮里有五次模型往返，换到一半没人看得出来）、账本只换属性不换本子
（`meter.retarget()`，否则"今天花了多少"会归零）、记忆抽取器跟着换、换过的 id 落盘
（刷新回到默认那个 = "换了没生效"）。回执是 `{t:'model', ok, id, usage}`，
**成功和失败同一条事件** —— 两个名字迟早有一边忘了处理，屏幕上就停在"换…"。

本地服务怎么指：`MODEL_LOCAL_BASE=http://127.0.0.1:11434/v1`（默认值就是它）。
集群里要指向 ollama 的 Service 名，例如 `http://ollama.app-xxx.svc:11434/v1`。

自测：`node agent/models.test.mjs`（64 项，查三态齐全、不可用必写原因、价格 null≠0、
id→接口的翻译只有一处）。

**两个只会在真浏览器里现形的坑**（自测全绿也挡不住，都踩过）：

1. **`.ag-layer` 是 `pointer-events:none`**，面板要自己 `pointer-events:auto`。
   少了这一行：玻璃看得见、点不动，而 DOM 的 click 不报错 —— 线上第一次就是这样。
   `el.click()` 绕过命中测试，所以要验"能不能点"，看 `document.elementFromPoint()`
   或走 CDP 的 `Input.dispatchMouseEvent`（真实鼠标）。
2. **粒子框只有一个**。它画的是"哪块空间被圈住了"，而两块玻璃（思考过程 / 换模型表）
   同时只开一块 —— 挪过去比再开一个划算（第二个框要多吃 1140 个槽位，那是场景的预算）。
   框的几何必须在 `setOpen(true)` **之前**改，否则它先在老地方亮起来再跳过去。
   `closePicker()` 是唯一出口（收玻璃 + 收框 + 还光标），`picker.close()` 直接调会留一个亮着的框。

### 设置页：接口 / 提示词 / 行为（`settings.mjs` + `shell/src/settings.js`）

换模型那张表只覆盖"已经写在表里的那些"。真正只能改 `.env` 再重启的还有三件，现在都在
状态条最右端那个「设置」里：

**存在的文件**：`agent/config/settings.json`（集群里挂 `state/<user>/config`，
和会话/账本同一个理由 —— 它是**用户配的东西**，换个 tag 就该还在）。
`0600`，因为里面有 key。`.gitignore` 和 `.dockerignore` 都挡掉了它。

#### ① 接口：加一个新的 API 地址

任何 OpenAI 兼容端点。加完就出现在换模型那张表的第三组「自定义」，
id 形状 `x/<providerId>/<模型名>`（模型名里可以有 `/`）——
`routeOf()` 仍然是唯一知道这个前缀是什么意思的地方。

这一组和另外两组的区别是**诚实**：那个模型会不会想、会不会调工具，我们没测过，
表里就写 `?`（`think`/`tools` 都是 `null`）。不按名字猜 —— 猜错的代价是
"标着会想，那栏里一个字都没有"，用户会以为界面坏了。价格同理：`null` →「未定价」。

地址必须替用户收拾，而且**要说出来**（面板底部那行）：

| 他填的 | 存成 | 为什么 |
|---|---|---|
| `api.example.com/v1` | `https://api.example.com/v1` | 没写协议时 `fetch` 直接抛 |
| `…/v1///` | `…/v1` | 拼 `/models` 会变成 `//models`，有的网关 404 |
| `…/v1/chat/completions` | `…/v1` | 从示例代码复制来的最常见形态 |
| `https://a/v1https://a/v1` | **拒** | 这个能通过 `new URL()`（host=a，path 里带着第二个 `://`），然后每轮都发到不存在的路径 |

**「测一下」不保存。** 它只问 `/models`：能连上吗、key 对不对、它有哪些模型。
一次回答三件事，比"发一句话试试"便宜得多；测通了不落盘是有意的 ——
一个按钮既测又存，失败时用户分不清是没连上还是没存上。

**key 三态**（面板里只显示 `已保存 …abcd`，不回明文）：

- 字段**没传** → 不改（面板没动它就不该动）
- **空串** → 清掉（本地网关不校验 key，这是合法状态）
- 非空 → 换掉

#### ② 提示词：默认追加，替换要过一道警告

`systemPrompt({append, replace})` 是唯一出口（`prompt.mjs`）。
**默认是追加**：内置那套（~9.7k 字）一个字不动，用户的写在末尾。

为什么默认不是替换：内置那段不是自我介绍，是**这块屏的说明书** ——
有哪些工具、`scene_show` 的字段是什么、label 最多几个字、一轮该说多少、什么必须查过才能说。
删掉它，模型照样聊天，但再也铺不出一屏，而用户会以为"它变笨了"。
想从零写的人确实存在，所以留了口子：切到"整段替换"会**预填内置全文**再让人改
（预填是唯一负责任的做法 —— 面对空白，人第一句会写"你是一个AI助手"）。

**空值一律当没写**：替换栏被删空不该让系统提示词变成空的。

#### ③ 行为：温度和步数

温度 0~1.2（>1 之后模型开始写错工具参数名，那看起来像"模型坏了"），
步数 3~30（默认 10）。步数是**安全网**，撞上也会先要一句结论（见上一节）。

#### 改完必须"接上去"（`applySettings`）

少了任何一条都会出现"改了没生效"：

1. `setCustomProviders()` 重新注入模型表 —— 否则要重启才看见新接口；
2. `_resetCache()` —— 平台/本地那两组有 TTL，删掉的接口还挂在列表里；
3. **所有活跃会话的第一条 `system` 换掉** —— 提示词是**配置**不是历史，
   但它以"消息"的形式存在会话里（`/api/debug` 才看得到模型当时被喂了什么）。
   不换的话：正在聊的那个会话继续用旧提示词，而刷新一下又"生效了"——
   一半生效是最难查的一种。
   `getSession()` 恢复历史会话时也走 `withCurrentSystem()`，同一个理由。

用着被删接口的会话会**退回默认模型**并发一条 note：不退回的话，
下一轮会往一个不存在的地址发请求，报错看起来像"网络问题"。

自测：`node agent/settings.test.mjs`（53 项）。

### 免费模型的实测：它们会"看"，但不可靠地"画"

同一句「机器怎么有点卡」，各跑三轮：

| 模型 | 延迟/步 | 结果 |
|---|---|---|
| Qwen2.5-7B | 0.9s | 调工具、铺屏都会，但常补旁白；约三分之一回合完全不铺 |
| Qwen3.5-4B | 15s | 三步走完、数字真实，最完整；但慢 |
| Qwen3.5-9B | 6s | 时好时坏，有一次只看了一个指标就停 |
| GLM-4-9B | 0.5s | 只看数据、写一段长解释，从不铺屏 |
| Xing-29B | 2s | 结构对，但会把 `ask` 写成字符串，偶尔把工具调用写成 `<tool_call>` 文本 |

结论与对策写在 `docs/场界面-设计与接口.md` §9，三层：

1. **接口分层**：默认用高层 `scene_show`（字段全平、不用 id/kind），
   六编码器的 `scene_set` 留给强模型。
2. **系统兜底**：模型看完数据没铺屏时，`defaultOverview()` 用真实读数铺一屏。
3. **规则进代码**：手势 `adjust` 回合里 `danger` 工具直接拒绝；
   整屏判重、每轮最多两屏、问完即停。

这套兜底是给"弱模型"准备的，现在默认换了会思考的 V4.1-Flash，它依然有用 ——
`scene_show` 调用失败、超时、429 的时候就是它在铺屏，和模型强弱无关。

换模型只改 `MODEL`，代码不用动（`DEFAULT_MODEL` **只在 `model.openai.mjs` 里写一份**）。

## 为什么下行 SSE、上行 POST

这条链路上真正需要"流"的只有服务端 → 客户端：一条工具的执行要分 `run` / `ok` 两次，
模型的话要逐句来，场景指令要能排队。上行是低频率的点击和输入，POST 就够。

SSE 是 HTTP/1.1 上最省事的流式方案，反代只要 `proxy_buffering off`（配置里已带
`X-Accel-Buffering: no`）。换成 WebSocket 只会多一个 Upgrade 握手和一套心跳要维护。

## 事件

### 下行（`GET /api/events?sid=…`，`text/event-stream`）

| `t` | 字段 | 意思 |
|---|---|---|
| `hello` | `sid model sys tools[]` | 连上了。`model` 是当前用的模型名（`mock:v1` / `sf:<模型id>`） |
| `resume` | `scene ops line` | 会话已有内容：把上一屏原样还回去。**不发动画** —— 用户没发起任何事 |
| `turn` | `round kind intent?` | 一轮开始。`kind` = `ask` / `intent` |
| `think` | `on step` | 模型在想。**前端拿它降相干度** —— 不是转圈，是"还没成形" |
| `say` | `text` | 模型说了一句话（一行，≤20 字） |
| `tool` | `id name args state ms note` | `state` = `run` / `ok` / `err` / `denied` |
| `scene` | `op spec ops kind at` | 场景指令，`op` = `set` / `patch` / `pulse` / `transition` |
| `approval` | `id tool args label danger` | 危险工具挂起，等一个 `approve` |
| `approval_done` | `id ok` | 挂起结束（批准 / 拒绝 / 超时） |
| `error` | `message` | 模型/网络出错。前端要**在场里说一句短话**（`模型账户没余额`），不能只写日志 |
| `note` | `message` | 系统级提示（例如"模型重复了同一组调用，已中止这一轮"） |
| `usage` | `ctx turn session day price limit cap final?` | token 账本。每步一次，轮末一份带 `final`（见「token 账本」） |
| `persona` | `items[{id,text}]` 或 `trace{ids,said}` | 人格层：这一轮注入了哪些旧事（`items`），以及它说出来的那句引用了哪几条（`trace`） |
| `busy` | — | 上一轮没结束，这次请求被丢掉 |
| `idle` | — | 一轮结束 |

### 上行（`POST /api/send`，body 带 `sid`）

| `t` | 字段 | 意思 |
|---|---|---|
| `ask` | `text` | 用户说了一句话 |
| `intent` | `intent` | 用户动了一下手（`adjust` / `pick` / `tap` / `pan`） |
| `approve` | `id ok` | 对挂起的审批给答复 |

`intent` 的 payload 就是 `gesture.js` 产出的那一份 —— 服务端不解释坐标，只解释语义：

```jsonc
{ "kind": "adjust", "target": "mem", "label": "内存", "from": 0.60, "to": 0.34, "delta": -0.26 }
```

## 状态不丢：会话落盘与恢复

这套界面的状态几乎全在"场"里 —— 刷新一下、反代重启一次，用户看到的就是一片空粒子，
刚才那屏和那行结论全没了。而那一屏往往是他正在看的东西，不是可以随手丢掉的过程。

所以每轮结束（`idle`）落一次盘：`agent/sessions/<sid>.json`，存三样 ——
对话（模型的上下文，只留最近 40 条）、**最后一屏**（眼睛看到的）、最后的读数（兜底要用）。
`sid` 存在 `localStorage`，刷新 / 新标签页都是同一段会话。

三个必须注意的地方：

1. **`patch` 要跟着存。** 只存 `set` 的那份 spec，恢复出来是"换问题之前"的那一屏 ——
   比空白更让人困惑。所以 `postOps` 记下最后几次 patch，恢复时先 `set` 再 `patch`。
2. **恢复不能有动画。** 用户没发起任何事，画面应该"已经在那儿"；重放一次溶解重组，
   等于告诉他"刚才发生了什么"。
3. **一个会话可以有多个连接。** 刷新的一瞬间旧连接还没断、新连接已经建好；
   开第二个标签页也是同一段会话。第一版是"新连接踢掉旧连接"，两个页面就会互相
   踢成 `disconnected` 然后各自重连，永远在打架 —— 现在是 `reses` 集合，广播。

## 首屏不要等模型

一轮里最慢的是模型（免费 7B 约 1~3s/步，三步就是 6~9s）。但**数据是快的**：
`sys_status` + `app_list` 加起来不到 2 秒。所以数据一到就先按真实读数铺一屏
（`defaultOverview`），模型想好之后再盖掉它。

用户看到的是"屏在长"，而不是"盯着一片抖动的粒子等它想"。
实测首屏从 4~9s 降到 **2.7s**，整轮 6.7s。

场里那一行字按字依次长出来（每字 42ms），这是场自己的编码方式，不是假装在流式输出 token；
输入回显走 `instant`，否则打字会像卡住。

## 工具契约

每个工具四件事写死（`tools.mjs`）：名字、给模型看的描述、参数 schema、**危险等级**。

危险等级只有两档，故意不做第三档：

| 等级 | 判据 | 处理 |
|---|---|---|
| `safe` | 只读，或只改变"看见什么"（`scene_*` 全在这档） | 直接执行 |
| `danger` | 会产生后果（写文件、删东西、重启服务） | 过审批门 |

"中间档"是所有权限系统烂掉的开始 —— 一旦有"半危险"，判据就模糊了。

## 审批门只有一条规则

> **用户通过分叉给出的明确选择，就是对那个动作的批准。**

已经点过"压到 34%"的人，不该再被问一次"确定压到 34% 吗"——那不是在保护他，
是在确认他没读过自己刚点的东西。所以：

- 手势 `pick` 触发的危险工具 → **直接做**（`needsGate()` 返回 false）
- 模型自己拿的主意（用户只说了"内存有点高"）→ **走审批**

审批 UI 复用场里那个分叉（`patch` 换文案），没有分叉时才退到 DOM 带子。
审批是**系统的 affordance**，不受模型表达自由支配 —— 所以它允许不是粒子。

## 这一轮怎么结束（回合循环）

**循环的退出条件是"模型不再要工具"，不是"走完 N 步"。** 这条是抄来的，也是踩出来的。

| 出处 | 循环怎么转 | 撞上限时怎么处理 |
|---|---|---|
| Anthropic（tool use 文档 /《Building effective agents》） | `while stop_reason == "tool_use"`，其它停止理由由应用处理 | 服务端循环回 `pause_turn`：意思是**没做完**，重发继续 |
| OpenAI Agents SDK | 输出分类成 final / handoff / tool_calls，只有 final 结束 | 抛 `MaxTurnsExceeded`（带上已有结果），不静默返回 |
| LangGraph | 图循环 | 抛 `GraphRecursionError` |

**共同点：「没有最终输出」是一个必须显式处理的状态，不能当成正常返回。**

我们原来是 `for (step < 5)` —— 把安全网当成了正常终点：第 5 步用完就跳出循环，
**从来没有再问过模型"那你说结论"**。用户问"系统里装了什么"，它查了五次，
然后屏幕上什么都没有（复现脚本 `.tmp/repro-silent.mjs`，看下面"怎么复现"）。

现在只有两条路能结束一轮：

1. **模型不再要工具** —— 它给出了回答（正常终局）；
2. **没有进展 / 太久 / 上下文满 / 空回复** —— `stop` 记下原因，出去**必须收口**。

### **次数不是"结束"的理由**（2026-10-23 改）

`MAX_STEPS` 曾经是 5、后来 10、造工具 16 —— 出发点都是省钱，但那个算盘打错了一件事：
**长任务本来就需要几十次工具调用**。翻三层目录、装完再验一遍、把五个组件的版本来历
全查一遍，20 步是常态。掐在 10 步上，用户看到的是"它做了一半就不做了"，
而这种失败**看起来像模型能力问题**，其实是循环的形状问题。

所以 `MAX_STEPS` 默认 **0 = 不限**。判"该不该停"换成三条，全都不数次数：

| `stop` | 判据 | 停下来的性质 |
|---|---|---|
| `stuck` | 同一组 `name:args` 连着 2 次 | 真没进展（多跑几次只会把同一个动画重播） |
| `long` | 单回合墙钟 > `TURN_HARD_MS`（15 分钟） | **可续跑**：中途汇报 + 说「继续」 |
| `ctx` | 上下文 ≥95% 且折不动了 | **可续跑** |
| `cap` | 只有用户自己在设置里填了步数才会出现 | 可选的安全网 |
| `silent` | 模型这一口气没接上（空回复） | 真故障 |

不设限的代价是"一轮可能跑很久"，所以配了两样东西：

**① 心跳（`progressLine`，每 45 秒）。** 长任务最怕的不是慢，是**安静** ——
屏幕上粒子在抖、一句话没有，和"卡死了"没有区别，用户会去刷新。
> 还在跑：第 12 步 · 已 2 分 10 秒 · 调了 11 次工具

**② 一轮之内的上下文折叠（`history.mjs` 的 `foldToolResults`）。**
步数放开之后，吃满窗口的不再是"聊了很多轮"，而是**这一轮干了很多事**：
三十个工具结果、每个几 KB。到 78% 就把最老的折成"一句说明 + 开头 240 字"，
**只动内容不动结构**（`tool_call_id` 全留着，所以永远不会 400）。
对比 `trimHistory`：那个要撞"切点必须落在 user"—— 而本轮只有开头一个 user，
往后无 user 可切，只能往回退到本轮开头（这就是为什么 `trimHistory` 现在也改成了
"回溯到 user"而不是 `length - 2`；后者会切在 `assistant(tool_calls)` 和 `tool` 之间）。

**③ 停下 ≠ 结束。** `long` / `ctx` / `cap` 收口时会说一句
「说「继续」就接着查 —— 前面查到的都还在」。历史里全是查到的结果，
用户一句「继续」就是新一轮（工具重新发、步数重新算），不是从头再来。
`stuck` / `silent` **不给**这个暗示 —— 那里没有"接着做"可言。

### 收口（`finalize()`）

不给工具（`tools: []`），再问它一次：*用已经拿到的结果直接回答用户的问题；
没查到就说清查了什么、拿到什么、卡在哪一步。2~5 句，不要道歉。*

拿到的文字**强制**上屏（`putVoice(force)`）—— 这一轮很可能已经说过一句"我先看看"，
不强制的话，真正的结论会被那句客套按"长回答优先"挡掉。

**为什么撤工具表而不是写 `tool_choice:'none'`**：那个参数不是每个服务端都认
（`required` 已经被拒过，见 `model.openai.mjs` 的降级），而"没有工具可用"
在任何 OpenAI 兼容接口上都成立 —— 空表意味着适配器根本不带 `tools` 字段。

### 最后一道闸（`closeFallback()`）

模型连"总结一下"都不说（或者收口那一问也超时了），就**由系统说一句实话**，
只用这一轮真发生过的事：

> 我查了 10 次（看目录），其中 10 次没成，但没能把这些串成答案。要接着查就说一声。

**不装作答上了**，也**绝不拿不相干的东西顶上**。原来那条记忆兜底只看"它没说话"、
不看"它有没有在查别的东西"，于是问"系统里装了什么"会看到"我记得这件事" ——
答非所问比空白更糟：用户会以为它答了，只是答歪了。现在那条多一个前提：
**它这一轮压根没动手**（`!s.acts.length`）。

### 五个实测过的坏模型（`agent/loop.test.mjs`）

`tools/dev/stub-flaky.mjs` 是一个**故意坏掉**的桩，五种样子都必须有结局：

| 模式 | 长什么样 | 谁收的口 |
|---|---|---|
| `long` | **正常的长任务**：连查 14 次，然后自己给出回答 | 不该有人收口 —— 不设限就必须走完 |
| `loop` | 每步都调工具、参数还都不同，从不说话 | 撞（显式设的）`MAX_STEPS` → finalize |
| `stuck` | 每步调同一个工具、同一组参数 | 重复检测 → `stop='stuck'` → finalize |
| `mute` | 空回复（没有 content 也没有 tool_calls） | `stop='silent'` → finalize |
| `dead` | 连"你说结论"也不理 | `closeFallback` 说实话 |

`long` 这条是**主判据**：`MAX_STEPS=0` 时它必须走满 14 步、并且**不是被收口逼出来的**
（日志里不能有 `closing` 请求）。这条如果挂了，说明"不设限"只是嘴上说。
`dead` 还必须说出**真的查过什么**（"查了 4 次（看目录）…"），不能只说"我失败了"。

这一份分两段：**纯逻辑**（`turnstop.mjs` 的几句措辞 —— 收口问什么、
心跳说什么、系统最后说什么、界面上那行原因、什么时候暗示「继续」）
+ **端到端**（上面那五种模型）。

为什么拆：端到端要起真 server、走本机回环，而 GitHub runner 上这条路不可靠
（同一个地址 `fetch` 报 ECONNREFUSED、`http.get` 却拿到 503 —— 两条路径互相矛盾）。
那里会自动跳过端到端并打印原因，纯逻辑照跑。**端到端的结论以本机为准**。

### 阈值

| 机制 | 值 | 为什么 |
|---|---|---|
| `MAX_STEPS` | **0 = 不限（默认）**；显式设 >0 时造工具那几轮另有 `MAX_STEPS_FORGE` | 长任务本来就要几十次工具调用。判"该停"看有没有进展，不看数了几次 |
| `TURN_HARD_MS` | 15 分钟（`TURN_MS` 仍认，作别名） | 一次 HTTP 回合挂太久，用户已经不知道它在干什么；到点收口，**但可续跑** |
| `BEAT_MS` | 45 秒 | 长任务不能安静地跑。这一句几乎不花钱，却把"在干活"和"卡死了"分开 |
| 重复调用检测 | 同一组 `name:args` 连着 2 次 → 收口 | 多跑的那几次会把同一个动画重播八遍，看着像"东西在抽" |
| 上下文折叠 | 78% 起折最老的，留最近 6 条；≥95% 还折不动 → `stop='ctx'` | 一轮里几十个工具结果才是吃窗口的大头 |
| `APPROVAL_MS` | 90s | 超时按拒绝处理，不无限挂着 |
| `CTX_TRIM_AT` / `CTX_TRIM_TO` | 78% → 45% | 轮**之间**到线就丢最老的一段（见下） |
| 429 退避 | 1s / 3s / 7s，共 3 次 | 免费模型的限流窗口是"每分钟 N 次"，500ms 重试等于没重试 |

**别再回到"默认 10 步"。** 那个数在 2026-10 被两次改过（5→10→不限），
每次的理由都一样：用户看到"它做了一半就不做了"。真怕花钱就开 `TOKEN_DAY_CAP`
（日账本，整账户级），或者自己在设置里填步数 —— 但默认不该替用户做这个决定。

**历史上那个"从 5 提到 10"的结论，现在只对了一半**：5 确实太紧（问"装了什么"要翻
两三个地方，而第一步还被强制取证占着），但 10 也只是"比 5 松一点"，遇到真长任务
照样半路死。正确的那一刀不是调数字，是把判据从"几次"换成"有没有进展"。

### 怎么复现"它去查了，然后没有然后"

`node .tmp/repro-silent.mjs loop|stuck|mute|dead` —— 起假模型 + 真 server，
问一句"系统里装了什么"，只数一件事：这一轮结束时屏幕上有过话吗。
改之前 `loop` 的结论是"最后一句话是**我记得这件事**"；改之后都有结局。
`long`（14 次调用然后正常收工）是反方向的判据：**不设限时不许有人来收口。**

## token 账本（`usage.mjs`）

**看不见的东西管不住。** 这个文件回答三个问题，三份数字都来自同一份 `usage`：

| 问 | 字段 | 从哪来 |
|---|---|---|
| 当前上下文有多大 | `ctx.tokens / limit` | 最后一次调用的 `prompt_tokens` |
| 刚才那一轮花了多少 | `turn.in / out / calls / cached` | 本轮所有调用**累加** |
| 今天一共多少 | `day.in / out / cost` | `agent/usage/<日期>.json`，跨会话累计 |

前两条进 SSE 的 `usage` 事件（每步一次 + 轮末一份 `final`），第三条落盘。手工查：
`GET /agent/api/usage?sid=<sid>`。界面上是 `?dev=1` 时右下角那个角标。

### 四条实测结论（真模型 + 真集群，2026-10-21）
1. **`prompt_tokens` 就是上下文大小**，不要自己累加历史。每次请求都把
   system + 记忆注入 + 全部消息重发一遍，所以最后一次的 `prompt_tokens`
   恰好是"现在占了多少窗口"。累加反而会因为重试、裁剪、注入而算错。
2. **一轮 8 步 = 10 万 token 输入**，是单次上下文（12k）的 8 倍。
   账本上 `turn.in` 远大于 `ctx.tokens` 不是 bug，是**多步任务的真实成本**——
   这也是"别让模型原地打转"的经济理由。
3. **上下文的大头不是历史，是工具表和系统提示词**。34 个工具的 JSON schema
   占 6.3k，系统提示词 5.9k，而一整轮对话的历史只有 1.5k。
   所以在 `MAX_STEPS` 和"裁历史"上省下的都不多 —— 要省得先裁工具表。
4. **缓存命中是真实存在的**：`cached` 实测占输入的一半（64k/104k）。
   同一份 system + tools 连着发，服务端会命中前缀缓存。

### 上下文是怎么从 12.4k 降到 9.4k 的

| 手段 | 省了多少 | 代价 / 判据 |
|---|---|---|
| 造工具的规程（1500 token）不进常驻提示词 | −1270 | 靠 `coldAllow()` 的关键词决定发不发；漏判的代价是"它说做不到"，所以关键词宁可宽 |
| 造工具那 6 个工具按场景发（`TOOL_GROUPS`） | −1290 | 同上，两组共用一次判断 |
| `scene_set` 与 `scene_transition` 合并成 `scene_set{op}` | −400 | 少一个工具要选；旧的 `scene_transition` 保留为 hidden，`exec` 仍认 |
| `sys_status` 连应用状态一起返回，`app_list` 变 hidden | 整整一步 | 单次返回多 100 token，换来少一次 9.4k 的完整重发 |
| 一轮步数 8 → 5 | 当时 −40% | **已经完全还回去了**：先改回 10，2026-10-23 再改成"不限"（见"次数不是结束的理由"）。掐断而不收口，省下的是钱，丢掉的是答案 |

**不要把这些省下来的钱花在"再砍一刀"上。** 再往下砍就得动工具集本身
（比如按模型能力只给 7B 12 个平铺动词），那会改变模型能做对什么，
需要一整轮回归才能确认没退化。

**步数那笔账要诚实看**：5 步 × 9.4k 确实是 8 步 × 12.4k 的 40%，但那是靠"五步之后
不管有没有结论都停"换来的 —— 代价就是"它去查了，然后没有然后"。现在回到 10 步，
这部分省下来的钱等于还回去了。真正管成本的应该是**不白跑**（重复检测、收口、
墙钟），不是**少给步数**。

### 两条纪律

- **没有单价就不算钱。** 查不到的模型 `price: null`，界面写"单价未配置"，
  绝不能填 0 —— "¥0.0000" 和"免费"在屏幕上长得一样，含义完全不同。
  价格会变，所以只在表里放**确定是 ¥0** 的模型，其余走
  `MODEL_PRICE_IN` / `MODEL_PRICE_OUT`（元/百万 token）。
- **估算值必须自己承认。** mock 模型、本地桩、某些网关不回 `usage`，这时按字数推
  （CJK 一字一 token，其余四字符一 token），并打 `est: true`，界面上带 `~`。
  估算值和账单长得一样，是这个功能最坏的失败方式。

### 可调项

```bash
# MODEL_CTX=32768            # 上下文窗口。不填按模型名查表，查不到落 32768 并标 `?`
# MODEL_PRICE_IN=4           # 元/百万 token，两个一起给才生效
# MODEL_PRICE_OUT=16
# TOKEN_DAY_CAP=2000000      # 今日 token 上限。到了直接拒下一轮（默认不限）
```

`TOKEN_DAY_CAP` 是**开跑前**拦的，不是跑完再报 —— 限额的意义就是不让它开始。

### 还没做

**上下文满了不会自己收。** 现在只能看见水位（≥75% 变暖色），没有策略：
到了 90% 该裁历史、还是该把旧工具摘掉、还是该换更小的工具表，都还没定。
在这之前它表现为"模型开始忘掉前几轮"，而观测之前的排查全靠猜。

## 怎么量它有没有变蠢（`tools/dev/eval-llm.mjs`）

```bash
SYS=k8s MODEL=Qwen/Qwen3-8B PORT=8788 node agent/server.mjs &   # 免费、慢，但够跑对照
node tools/dev/eval-llm.mjs        # 五道常问题，每题一个干净 sid
```

五列对应五种坏法：**步数**（越贵）、**无效调用**（被拒 / 参数坏）、**工具序列**（乱调、绕路）、
**输出通道**（一声不吭是最严重的失败）、**输入**（本轮 token）。

### 上下文长度到底有没有影响：三点对照（2026-10-21）

用 `CTX_PAD` 在系统提示词后面追加无关占位文字（不改任何规则），同一组题各跑一遍：

| 上下文 | 平均步数 | 工具选择 | 完成 |
|---|---|---|---|
| 9.4k | 2.0 | sys_status / fs_scan / memory_recall | 3/5（另 2 题被限流） |
| 12.4k（+3k 无关文字） | 2.0 | **完全相同** | 3/5 |
| 23k（+14k 无关文字） | 2.0 | **完全相同** | 3/5（后 2 题 429） |

**结论：在 9~24k 这个区间里，上下文长度对 7B 的行为没有可测量的影响。**
真正让它从"8 步乱调"变成"2 步做完"的是三件设计上的事，不是长度：
合并 `sys_status`+`app_list` 少了一个可乱调的工具、步数上限收到 5、坏了参数不再给
"去调 tool_write"的错误建议。

**这条要先量再下结论。** 没有 `CTX_PAD` 和这五道题，"上下文太大了所以变蠢"永远只是感觉 ——
而按这个感觉去砍提示词，很可能砍掉的正是让它做对的那几句。

### 已知的真问题：免费模型限流

连跑 15 题之后开始出现 `429 Request was rejected`。免费模型的速率限制很紧，
它不是"变蠢"，但表现出来一样（这一题毫无反应）。评测脚本会把 429 单独标出来，
不算进"变蠢"的账里。

## 上下文满窗自收（`history.mjs`）

32k 窗口里固定开销（系统提示 4.8k + 工具表 4.6k）已经占了三成，十几轮就能吃满。
吃满时接口直接 400 —— 而且**报错发生在工具跑到一半**，用户看到的是"做了一半不动了"，
比一开始就拒绝还难理解。所以到线之后由服务端自己丢最老的一段。

三条写进测试的规矩（`node agent/history.test.mjs`）：

1. **切点必须落在 `user` 上。** `assistant(tool_calls)` 和随后的 `tool` 结果是一条
   消息链，切断任何一处下次请求直接 400，而且报错长得像"模型接口坏了"。
   一轮对话总是从 `user` 起头，从它切天然完整。
2. **第一条 system 永不裁。** 丢了它就是丢身份和全部规则。
3. **固定开销本身就超过目标水位时，不假装裁过了。** 返回 `cramped`，上层如实说
   "系统提示和工具表本身就把窗口占满了" —— 那时候该做的是裁工具表，不是裁历史。

不摘要：摘要要再调一次模型，而**那次调用的上下文本来就是满的**。
要做也应该在后台做，不挡这一轮。

### 压缩（`/compact`）与新会话（`/new`）

上面那条"直接丢"解决的是**接口 400**，不是"用户还想接着聊"。所以现在有两条路，
顺序是**先压缩，压不动才丢**：

| | 压缩上下文 | 开新会话 |
|---|---|---|
| 目的 | 同一件事聊太长，腾地方接着聊 | 换一件事，别被前面带着走 |
| 会话 id | 不变 | 换新 |
| 屏幕上 | 内容还在 | 清空 |
| 上一段 | 变成摘要，仍在上下文里 | 变成**一条记忆**，靠 recall 取 |
| 记忆 / 账本 | 不动 | 不动（**这正是"新会话"≠"失忆"**） |

**压缩**（`history.mjs` 的 `compactPlan` / `applyCompact`，`server.mjs` 的 `compactSession`）：

- 到 78% 时**先摘要再替换**，摘要那条是 `user` 角色并带身份标签
  （"以下是更早对话的摘要，不是原话"）—— 不标的话模型会把摘要当事实引用，
  而我们不允许"模型自己的话"变成事实。用 user 而不是改 system：改 system 会把前缀缓存打掉。
- 切点仍必须落在 `user`；窗口太窄时**往回**退到最近的 user。
  踩过：兜底成 `length - 2` 会切在 `tool` 上，下一次请求直接 400 且报错像接口坏了。
- 手动 `/compact`（或「压缩一下」）走旁路，**不占模型一轮**；
  自动压缩有 60s 冷却，否则同一段水位会每轮花一次调用。
- 状态条的水位线改成一条来回扫的带子：摘要要多久取决于模型，进度不可知，
  所以不画进度条（画了就是编数字）。

**新会话**（`newSession`）三件事缺一不可，少一件用户就觉得"它把我刚说的忘了"：

1. 上一段压成**一行 episode** 写进记忆（`kind: 'episode'`）—— 新会话里问
   "上次那个日志"，`memory_recall` 能取到；
2. 换 sid、清屏、重建系统提示，**新会话立刻落盘**（否则刷新会随出一个新 id）；
3. 旧会话归档到 `sessions/archive/<sid>.json`，不删。
   归档后置 `s.dead`，否则回合结束的 idle 保存会把刚移走的文件又写回来。

摘要**不**塞进新会话的第一条 system：那会让"新会话"没那么新，还重复占上下文。
需要时它自己 recall —— 记忆是**相关才取**，不是常驻。

## 官方技能（`skills.mjs`）

`olares-cli` 是 Olares 官方的命令树，每个子树配一份 `SKILL.md`（Claude 式技能），
12 份都编在二进制里（`skills list / read / export`）。**能力不用自己造，缺的是语义层。**

- 构建时 `olares-cli skills export /app/agent/olares-skills` 落成文件，
  运行时**不 spawn**（`skills.mjs` 只读盘）。
- 展开时压到 400~840 字：只留「该用的场合」+ 命令样例 + 症状路由表。
  英文长文（5~17KB）整份塞给 7B 等于把窗口吃掉一半，而且它会开始只复述。
- `skill_use` 工具**同时返回 `ops`** —— 文档是动词表（几十个），
  `olares` 的 op 是能执行的那一小撮（16 个）。两个都递过去，模型才知道
  "这个系统能干这件事，但现在我只能看到这几样"。
  `chart` / `publish` / `router` / `search` / `knowledge` 还没接，表里就是空 ——
  那时候要照实说"这块还没接"，**不要现场编命令**。

为什么不在运行时调 `olares-cli skills read`：要 spawn，而且输出是给人读的长文；
更重要的是一份 `skills.test.mjs` 能钉住"压完还看得懂"这件事（行边界、体积、症状表）。

## 系统层：官方 CLI 的受控出口（`olares.mjs`）

一个工具 + `op` 枚举，不是十几个平铺工具（每个 schema 进上下文约 150 token）。
`op` → **固定 argv 数组**，模型只填枚举和名字，拼不了字符串。

| op | 命令 | 回答什么 |
|---|---|---|
| `apps` | `market list --mine` + `dashboard applications` + 分母 | 装了哪些、版本、状态、各自占多少 |
| `app` / `appinfo` | `market status/get` | 卡在哪（progress/message）、是干什么的 |
| `catalog` / `categories` | `market list` / `categories` | 能不能装、有什么分类 |
| `overview` / `usage` | `dashboard overview` / `applications` | 整机负载、谁在吃资源 |
| `pods` / `events` | `cluster pod list` / `pod events <n> -n <ns>` | 排障：重启次数、waiting 原因、事件 |
| `images` | `doctor images` | 磁盘被什么占了（**引用数字段是 `refs`**） |
| `backup` / `users` / `appcfg` / `context` / `version` / `whoami` | 对应子树 | 备份计划、用户、入口、ISO 视野 |

**原始输出必须 shape**：`cluster pod list` 366KB、`market get` 32KB、`images` 85KB。
压完分别是 856 字 / 几百字节 / 8 条。字段名是**猜的**，所以有 `olares.test.mjs`：
夹具是 2026-10-22 从线上 pod 抓的真货（`agent/fixtures/olares/`），不改字段只截条数。
这条测试挡的是"屏幕上不报错、只是少一个数或说一句假话"的那类错误
（踩过：`in_use` 猜错 → 179 个镜像全说成没人用；`memPct` 当整机 → 2% 说成 0.22%）。

### 身份：**程序自己登，不叫用户开终端**

`olares-cli` 的 `profile list` 有六种 status，判据写在 CLI 自己的 `auth.md` 里，
我们这边只有 `authState()` 一处翻译：

| status | 含义 | 我们的动作 |
|---|---|---|
| `logged-in` / `unknown` | 能用 | 干活 |
| `expired` | access token 过期，**下一条命令会自己刷** | **干活**（别拦） |
| `pending` | 平台发的 profile 还没交换 grant | 干活（下一条命令交换） |
| `invalidated` / `never` | 服务端拒了 refresh / 从没存过 | 自己重登一次，再干活 |

踩过一次，而且踩得像"设计如此"：原来判 `status.includes('logged')`，
于是 `expired` 被当成"没授权"，工具直接回一句**"去终端跑 `olares-cli profile login`"**。
实测（2026-10-23）：pod 里 profile 一直是 `expired`，而 `market list --mine` 照样跑通
（它自己刷了，跑完 `profile list` 就变 `logged-in`）—— **我们拦住了一次本来会成功的调用，
还让用户去开终端。**

所以闸门和自救必须在一起（`ensure()`）：`expired` 直接放行；真失效时**先自己登一次**
（冷却 5 分钟、单飞），登不上才说话。恢复凭据从环境变量来，走同一个 Secret：

| 变量 | 说明 |
|---|---|
| `OLARES_ID` | 用哪个身份登录（不给就用 profile list 里那个） |
| `OLARES_REFRESH_TOKEN` | 优先：不用密码，改密码也不失效 |
| `OLARES_PASSWORD` | 兜底：密码只走 stdin（`--password-stdin`，不进 argv / `ps`） |

`warm()` 在启动时也走这条路 —— 起来发现身份坏了就自己接上，
用户不该知道 token 有过期这回事。没配凭据时，工具返回的话里**不许出现**
"去终端敲命令"，只说明缺哪个变量（`agent/olares.test.mjs` 钉住了这一条）。

### 写操作（`olares_act`，P5）

停 / 开 / 重启 / 装 / 升级 / 卸载 / 取消 —— **单独一个工具，level=danger**。

*不复用 `olares` 的 op 枚举*：那个是 `safe`，而审批门按**工具名**判 level
（`s.tools.level(name)`）。把危险动词混进 safe 的枚举里，等于开一个
"看参数决定要不要审批"的口子 —— 那种判据迟早漏一个。

三条实测规矩：

1. **写操作自己不带终态**。`market stop` 返回 `{status:"accepted"}`，
   终态要再查一次 `market status`（`state: "stopped"`）。
   所以 `accepted` 一律回一句"服务端收下了，还没结束" —— 不能让模型说"已经停好了"。
2. **`--watch` 的超时要比 exec 超时短**（90s vs 130s）。反过来 CLI 还没说话
   就被我们掐了，报出来的是"超时"而不是"还在装"。
3. **写完清读缓存**。否则下一次 `apps` 拿到的还是写之前那 15 秒的快照，
   用户会看到"我明明停了它，怎么还显示 running"。

审批卡按动词说代价（停 ≠ 卸载），并且 `ACT_WORDS` 要认得"停掉 / 开回 / 升级 / 取消" ——
少一个，"帮我停掉 n8n"就会被判成"只是问问"，模型查完状态就停住，用户以为自己说清楚了。


## 画图：ComfyUI（`comfy.mjs` + `workflows/*.json`）

一个工具 + 三个 op，和 `olares` 同一个形状（模型记不住十个名字，一份 schema 就是 150 token）：

| op | 做什么 |
|---|---|
| `status` | 连得上吗、**有没有显卡**、队列多长、有哪些模型、有哪些模板 |
| `templates` | 有哪几种画法（方图 / 竖图），每种带尺寸档和步数 |
| `gen` | 真的画一张：`template` + `prompt` + 可选 `width/height/steps/seed` |

**模型不能写 workflow。** 图归服务端（`agent/workflows/*.json`，`__PROMPT__` 这种占位符），
模型只填能填的那几个槽。两条理由：① 一张图 2~5KB 的节点 id + 连线，7B 一定写错；
② "任意图"等于"任意节点执行"，那是安全口子。和 `scene.schema.mjs` 的白名单同源。

**这台机器没有显卡也能开发**，这是这次改动的重点：

| 层 | 用什么 | 验什么 |
|---|---|---|
| 协议桩 `tools/dev/stub-comfy.mjs` | 照真契约实现 `/system_stats` `/prompt` `/history` `/view` `/queue` `/object_info` `/interrupt`，返回**真 PNG**，可注入 `FAIL=oom\|badgraph\|queue` | 排队、轮询、超时、错误映射、图片字节 —— 和显卡无关的那 90% |
| 本机 CPU 真跑 | `./deploy/comfy.sh`（自己起的 ReplicaSet，见下） | 真图、真延迟：**约 78 秒/步**（这台 8 vCPU 的 matmul 只有 ~12 GFLOPS），4 步 512×512 一张 5~6 分钟 |
| 远端有卡的机器 | 任何 ComfyUI，改 `COMFY_URL` 就行 | 出片质量 |
| 录放 | 真跑一次，把 `/history` JSON + 输出 PNG 存成夹具 | 防"字段名猜错"（`outputs[节点].images[].filename` 这类结构最容易被猜错） |

### 市场里那个 ComfyUI 装不上，所以自己起一个（`deploy/comfy-cpu.yaml` + `deploy/comfy.sh`）

`olares-cli market get comfyuisharev3 -o json`（1.1.38）里 `accelerator` 只有三档，
**全是 GPU**：`nvidia`（2Gi VRAM）、`nvidia-gb10`、`intel-gpu`（2Gi）——全文没有 `cpu`；
而且每档 `requiredMemory` 20~22Gi，**比这台机器整机内存（15.6GB，allocatable 10.6Gi）还大**。
两道门各自都能挡住它。改安装包也不是好选择：chart 在 `market.olares` 远端源，升级即覆盖；
镜像 `beclab/comfyui:*-launcher` 是 CUDA 构建，launcher 里怎么起 python 是写死的。

所以走和桌面壳层同一条路：ReplicaSet（`appns-validating-webhook` 只拦 deployment/sts/ds 的 CREATE）
+ Service，`/root` 整个挂 hostPath（第二次启动不用重拷 bundle、模型不用重下）。

```bash
./deploy/comfy.sh              # 起（幂等）：apply → 等 ready → 写 Secret → 重启 agent → 从 agent 侧验一次
./deploy/comfy.sh --status     # 只看（pod / 模型 / 服务 / agent 看到的 COMFY_URL）
./deploy/comfy.sh --logs       # 跟日志（下模型、启动、采样进度都在这里）
./deploy/comfy.sh --down       # 停（模型留在盘上）
./deploy/comfy.sh --purge      # 连模型一起删（2.1GB）
```

镜像 `yanwk/comfyui-boot:cpu`（3.6GB，amd64）。它的 entrypoint 是
`python3 /root/ComfyUI/main.py --listen --port 8188 $CLI_ARGS`，
所以「CPU」只是 `CLI_ARGS=--cpu` 一行 env，不碰镜像。

### 参数由设备决定，不是由模板决定（`profileOf`）

模板只提供**形状**（一张图的节点连线、方图还是竖图）；档位（步数、最大边、等多久）
由 `profileOf(/system_stats)` 推出来 —— 这是这次加的"适配器"：

| 输入（ComfyUI 自己报的） | 推出的档位 |
|---|---|
| `devices[0].type` 含 cuda/rocm/mps/xpu 且 `vram_total > 0` | `gpu`：6 步；显存 ≥8GB 允许 768 边，否则 512 |
| 没有卡 | `cpu`：4 步、512 边；`system.ram_total < 6GB` 再降到 3 步、384 边 |
| 预计时间 | `secPerStep × steps + 40s`（载权重/编码/解码）。CPU 的 105 秒/步是**这台机器四次实测的中位数**（82 / 100 / 106 / 137），换机器用 `COMFY_SEC_PER_STEP` 覆盖 |
| 说给用户的数 | `etaMin: [下界, 上界]`（etaSec 的 0.85~1.35 倍）。**不给单点** —— 共享 CPU 上单点数必然有一半时间不准 |

`status` 直接把结论交出去（`recommend: {template, steps, width, height, etaSec}` 和一句
`advice`），工具描述也改成**"steps 和尺寸不要自己猜"**：模型没有理由去记住"78 秒/步"
这种数字，它只要照着说给用户听。同理 `gen` 在不传 steps/尺寸时按设备档取；
被设备档缩小的尺寸会在 `adjusted` 里说明，不许悄悄改（"我要 768 出来怎么是 512"）。

**这台机器实测的数字**（别按显卡的直觉估）：

| 项 | 值 | 说明 |
|---|---|---|
| 权重 | `Lykon/dreamshaper-8-lcm` 2.13GB | SD1.5 + LCM，免登录。不用 `sd-turbo`：`sd_turbo.safetensors` 5.2GB，光权重就吃掉 10.6Gi 可分配内存的一半 |
| 启动 | ~4 分钟到 `/system_stats` 可用 | torch import + 把 bundle 拷进 `/root`（只有第一次拷） |
| 采样 | **82~137 秒/步**（中位 105） | 四次真跑（扣掉 40s 固定开销）：8 步 697s=82、6 步 642s=100、4 步 463s=106、4 步 588s=137。差别来自整机争抢（load 30 时慢 60%）—— 所以对外说 **7~10 分钟**，不说 7 分钟 |
| 等待上限 | **不写死** | 设备档 ×2.5（纯 CPU ≈ 16 分钟），`COMFY_TIMEOUT_MS` 可强制覆盖。超时**不杀作业**，只是先回一句"还没出来" |
| 资源 | 6 核 / 7Gi | 不设 CPU 上限，torch 吃满 8 核，出图那几分钟整个桌面在卡；内存超限是 pod 自己被 OOMKill，不会拖死桌面 |
| 线程 | `OMP_NUM_THREADS=6` | torch 默认按**节点**核数（8）开线程，多出来的 2 个只会互相抢 |
| 精度 | `--force-fp32` | 微基准里 fp16 比 fp32 慢 55 倍（0.38s vs 20.6s / 10 次 768³），但换到整图只从 108 → 88 秒/步 —— **说明瓶颈是整机争抢，不是精度模拟**。保留 fp32，别指望那 55 倍 |

`comfy.sh` 里三件容易漏的事，都有注释钉着：`kubectl apply` 的 `-n $NS`（漏了 pod 落在
`default`，模型照样下完但 agent 找不到服务名）；Secret patch 的 JSON 要在**本地**拼好
（远端展开 `$B` 会被引号吃掉，写进去字面量 `$B`，kubectl 报 `illegal base64 data`）；
ReplicaSet **不会**因为 template 变了换 pod —— 靠 `emergent/tmpl-hash` 注解比对，
不一致才删（和桌面那边同一个坑）。

`install.sh` 里也补了一处：它写 Secret 是**整份替换**，`.env` 里没有的键会消失，
而 `COMFY_URL` 是 `comfy.sh` 单独写进去的 —— 「装了 ComfyUI 又跑了一次 install.sh」
会让画图静默坏掉（表现是"昨天还能画"）。现在发现 `comfyui` 服务在就把它补回去。

五条错误各有各的说法（自测逐个钉住）：`comfy_offline`（连不上，顺带提示"先用桩顶上"）、
`comfy_bad_graph`（指到具体节点）、`comfy_queue_full`、`comfy_oom`（说清"调到 512、步数降到 4~8"）、
`comfy_timeout`（**不打断**，把 `prompt_id` 交出来 —— 图可能还在跑，等会儿还能问）。

图片回到屏幕走 **`/api/comfy/img` 代理**，不让前端直连 ComfyUI：它可能在另一台机器上（没卡时尤其）、
跨源、端口暴露，而且路径要过白名单（只 `output`/`temp`、只 png/jpg）——
否则这个代理就是"读那台机器上任何文件"的口子。

上屏是**第四块玻璃**（`shell/src/imagepanel.js`）：原图 + 外面一圈同样的粒子流。
它不进 `scene` —— 场景层是模型能画的东西，图是工具的产物。三条踩过的规矩都在里面：
`pointer-events:auto`、框在 `setOpen(true)` 之前挪到真实盒子、收起只有一条出口。

> 一个只在真浏览器里才看得见的坑：图刚落屏，下一步的 `think` 会让「思考过程」自己弹出来，
> 而它开之前要收别的玻璃 —— 于是刚画好的图当场被收掉，用户只看到一句"画好了"和一片空场。
> 现在 `openTrace()` 遇到图就让位（过程仍在记，点小脸能看）；点小脸是明确要看过程，那时图才收。

## 「思考过程」：服务端出文字，前端只管画（`trace.mjs`）

一轮里真正发生的事有十几件：翻记忆、取证、跑工具、铺屏、等你确认。它们以前只进
`?dev=1` 的观察窗（10px 等宽，用户根本看不见）。现在有一条 `t: 'trace'` 事件专供那一栏。

三种 kind，对应三种行：

| kind | 形状 | 谁发 |
|---|---|---|
| `step` | `{ id, text:'看一眼机器', detail:'应用清单', tool }` | 工具开跑时（`id` 是 tool_call id） |
| `end` | `{ id, status:'ok'\|'err'\|'denied', ms, note }` | 工具结束时，**补回同一行** |
| `note` | `{ text, detail, tone:'mem'\|'gate'\|'note' }` | 记忆命中、审批等待、上下文压缩… |

**为什么翻译放在服务端**：前端拿得到工具名，但拿不到"翻到 2 条旧事""这一段压过了"这类
只有服务端知道的事；两个地方各写一份词典，迟早有一处开始漂（`agent/trace.test.mjs`
会检查**每个工具都有一个人话动词** —— 少一个不会报错，屏幕上那行会直接变成 `fs_list`）。

三条措辞纪律：

1. **动词 + 宾语**，不超过 9 + 24 字。`sys_status` 对用户来说是"看一眼机器"，不是函数名。
2. **不编造结果**。结果由 `summarize()` 给（它已经会说中文），`trace.mjs` 一个字都不猜。
3. **不做判断**。危不危险是 `tools.mjs` 的 `level` 管；这里只负责让一行字读起来像人话。

前端那半边在 `shell/src/trace.js`（玻璃 + 行）和 `shell/src/traceframe.js`（粒子框），
交互规则见 `docs/interaction-spec.md` §7.5。

## 限流（429）怎么处理

`model.openai.mjs` 里 429 单独一条路：先听 `Retry-After`，没有就 1s / 3s / 7s 退避
（加 0~400ms 抖动，避免多个连接整齐地一起回来），一共 3 次。仍失败就抛一个带
`limited` 标记的错误 —— 前端说"模型那边限流了，等会儿再问"，而不是把 429 原文糊到脸上。

**为什么值得单独写一条**：限流的表现和"变蠢"一模一样（这一题毫无反应）。
不把这两件事分开，排查会一直往模型能力上想。`node agent/model.retry.test.mjs` 用假服务端
把退避、上限、标记三件事都钉住了。

## 还没做

1. **L0.5 知识轨迹**（人格层的另一半）：每天按真实排名学一个新知识。默认关 ——
   它要出网、要成本、而且噪声大。种子和漂移先跑起来，再看要不要加这一层。
2. **种子来源只到"动作后果"这一层**：对话里的决策（"我们决定先不动 n8n"）还不进种子。
   它现在记得自己**做过**什么，不记得自己**决定**过什么。
3. **用户目录依赖 `FS_ROOT`**：`fs_scan` 读的是宿主机的 `/olares/rootfs/userspace`
   —— 和 Files 应用**同一个目录**，所以看到的是真文件。没挂上时如实返回"看不到文件"，
   绝不猜文件名（用户会照着假列表去删东西）。文件**写操作**（移动 / 删除）还没接。
4. **写操作**：`mem_trim` 在真集群上同样只返回"没接"。真机上"把内存压到某个比例"
   没有对应的系统动作，能做的只有重启应用，而重启**不保证**压到目标值。
   接之前要先想清楚"降内存"到底该是什么原子动作（`rollout restart`？scale 到 0？），
   不要为了链路完整去假装成功。
5. **单 pod 内存取不到时**：`kubectl top` 不可用（没装 metrics-server），
   所以应用内存只能靠 Prometheus 的 `container_memory_working_set_bytes`。
   这台机器上它好用；换集群如果没有 node-exporter / cAdvisor，应用列表会没有内存数。
6. **流式 token**：现在 `say` 是一整句到达。真模型要按 SSE 分块推，前端得支持"同一行字追加"
   （现在的"逐字生长"是渲染动画，不是真流式）。
7. **鉴权**：桌面入口本身在 Olares 登录之后（`desktop.<user>` 前面有 authelia），
   所以从桌面点进来的人一定是登录过的。但**裸端口没校验**：集群内任何 pod 都能直连
   `8788`。要更严就上 forward-auth（`authelia-backend-svc:9091/api/verify`，
   无 cookie 返 401，已实测）。比鉴权更紧的一层是 RBAC：现在是集群级只读 +
   代码里按命名空间后缀过滤，单用户等价，多用户会看到别人的 pod。
8. **审计**：每次工具调用落 `~/Agent/audit/*.jsonl`，返回值脱敏（抹 JWT / Bearer 形状）。
9. **`/api/debug` 已默认关闭**（需要 `DEBUG=1` 启动）。它会把整个会话消息原样吐出来，
   含系统提示词和记忆注入 —— 线上不该有这个出口。
