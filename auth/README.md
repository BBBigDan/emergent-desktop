# 粒子登录页

Olares 登录页的替代实现。**界面本身就是粒子**，没有半透明卡片垫底：
用户名、提示、输入框边框、光标、箭头、密码点，全部是从「墨稿」栅格化出来的点阵；
头像仍是真实照片（DOM `<img>`），外面包一层三层环流。

```
auth/
├── index.html          一个 canvas + 一个透明 input + 头像 img
├── src/ui.js           墨稿（照官方登录页量的布局）+ 覆盖率采样
├── src/field.js        粒子场：骨架 / 云层 / 头像光晕
└── src/login.js        Authelia 协议（md5 加盐、X-Bfl-User、targetURL）
```

本地跑：

```bash
node auth/serve.mjs 8822     # → http://127.0.0.1:8822/
```

**别用 `python -m http.server`**：它不发 `Cache-Control`，浏览器对 ES Module 会做启发式
缓存 —— 改完代码刷新还是旧文件；如果这个 origin 以前注册过 `scope=/` 的 Service
Worker，还会从它的 cache 里吐旧 `src/*.js`，怎么刷都没用。`serve.mjs` 统一发
`no-store`，并给 HTML 塞构建戳（控制台 `__build`）。

`/bfl/info/v1/olares-info`、`/api/state` 取不到时自动降级（用户名回落 `owner`），
所以纯静态也能看效果，只有提交密码需要真实后端。

## 三层粒子

这套结构是照 `prototype/src/main.js` 的物理搬过来的，不是重新设计的。

| 层 | 数量 | 行为 |
| --- | --- | --- |
| **骨架 skeleton** | ~1300（按墨稿格数） | 点阵本体。弹簧跟随槽位，**不是钉死**：整片被一个相干 fbm 流场推着缓慢起伏（±2px / 5s），弹簧略欠阻尼，所以一直有回弹 |
| **云层 cloud** | 2400 | 指针在时围着指针公转（半径 16–62px，逐粒子随机相位/角速度 → 剪切流动）；压到控件上时按「离控件中心由近及远」倾泻进该控件的**细网格槽位**，控件被灌满 → 变亮变密 = "更清楚"；挤不进去的其余粒子把半径外扩成光晕。指针离开 → 沉成 190–470px 的缓慢星尘 |
| **头像光晕** | 1100 | 贴身 / 中层 / 外雾三层环流，角速度内快外慢，亮度带沿圆周扫过（顶点着色器算，便宜） |

### 「不规整」是靠这四件事堆出来的

只有"1 个槽位 1 颗粒子 + 同一张贴图 + 同一档亮度"，出来必然是一张印刷网点图。
原型里是这四层叠加：

1. **过采样 1.3 倍**：4400 颗粒子铺 ~3377 个槽位。多出来的那颗有自己的弹簧/流场/相位，
   永远压不实 → 同一个格子上是一小簇微偏的复本。这里按 key 哈希让 46% 的格子多一颗，
   并给它 ±0.44 格的随机偏移（不是格心）。
2. **逐粒子点径 / 亮度差异**：`sJit` 0.82–1.20、`aJit` 0.78–1.06，由格子哈希决定
   （重绘不跳变）。每颗点都不一样大、不一样亮。
3. **加色混合（Additive）**：原型就是加色，重叠处会叠亮 → 簇上的点更白更热，
   单颗是冷青。用 Normal 混合永远得不到这种"热度分布"。
4. **连线层**：只点不连，边框就是一串孤立的珠子。连线让它变成一条连续发光的带：
   - 骨架：只连**线条类几何**（边框 / 箭头），文字绝不连（会织成网 = 糊），
     阈值 1.75 格、每颗最多 3 条
   - 增援·槽位：阈值 2.1 个细格 → 槽内短网，控件被灌成"实心"
   - 增援·公转：阈值 10px → 短划线随流动走（彗光滑尾）。

三个必须记住的结论（都是踩过的坑）：

1. **流场必须相干**。逐粒子 `sin(t + seed)` 做位移 = 噪点闪烁；按屏幕坐标采样 fbm，
   邻域受力一致，整片才像"形在呼吸"。为省算力，fbm 在 36×26 的粗网格上算一遍，
   粒子做双线性采样——视觉等价，便宜两个数量级。
2. **弹簧不能有死区**。曾经写成「距目标 < 0.15px 就吸附归零」，结果每颗粒子都钉死在
   格心，整页看起来像一张贴图。只要去掉吸附，同样的目标点立刻"活"了。
3. **聚合要有下限**。槽位粒子的微旋半径 0.9px（不是 0，否则死板；也不是 5px，否则糊）。
4. **加色混合要把亮度压回来**。加色下每颗点的贡献是 `color × alpha` 直接相加，
   沿用 Normal 混合的 alpha（0.7~1.0）会立刻叠成一片白。骨架 `gainS≈0.85`、
   单颗 alpha 0.5~0.8 才等于原型那种"青里透白的点"。

## 字体工程

点阵字能不能读，取决于**笔画占多少格**，跟字号关系没那么大。原型 v0.14 做过量化
（`.tmp/fontprobe.html` 用生产同款采样算法把候选字体点阵化）：

| 字体 | 笔画 ÷ 点距 | 结果 |
| --- | --- | --- |
| 微软雅黑 400 / SimHei | 1.2 格，4 邻域连通度 2.6–3.0 | 每个笔画横截面占 2 格，字怀被填死 → 糊成块 |
| **等线 Light (DengXian Light)** | 0.8 格，连通度 2.1–2.3 | 笔画恰 1 格、字怀留 1 格暗缝 → 能认 |

所以：

- 中文 `"DengXian Light" → "Microsoft YaHei Light" → "PingFang SC"`，字重 **300**
- 西文 `Bahnschrift Light → Bahnschrift`，字重 **400**（Light 在 30px 时笔画只有
  0.6 格，点阵会碎成散点；400 才够 0.84 格）
- 汉字之间加 **一格字距**：全角字默认紧贴，两个字会并成一团；居中时要补偿 `-track/2`
  （Chrome 把尾随字距算进宽度）
- 文字**不加描边**：加宽笔画等于把字怀填死，这是"糊"的另一半原因
- 点阵格 `CELL = 2.5`（**原型 SCAN_CELL 原值**）。字号 ÷ 2.5 要 ≥ 18 才有 18 格以上，
  汉字才立得住；格子上到 3.0 就得把字号再放大四分之一
- 点径 `1.06 × CELL`：硬芯圆点（`1 - smoothstep(0.82, 1.0, r)`），可见芯 ≈ 0.95 倍点距，
  **相邻点相切**（原型 0.86）。这是唯一正确的档位：
  `1.4+` 相邻点重叠 40% 以上 → 糊成一片光；`0.9` 以下 → 断成散珠

## 尺度：为什么必须换掉官方那个小卡片

官方登录页是 262×300 的卡片、14px 的提示字、124px 的头像 —— 那是为**实心矢量字**
设计的尺度。搬进点阵里，一个汉字只有 16.8 格（32px ÷ 1.9），笔画和字怀挤在一起，
怎么调字体、怎么调亮度都只有"散"和"糊"两种结果。

原型 UI 模式的坐标系是这样的：

| | 原型 | 本实现 |
| --- | --- | --- |
| 逻辑画布 | 760×490 | 600×400 |
| 点阵格 SCAN_CELL | 2.5 | **2.5（相同）** |
| 上屏缩放 | 2.59（`UI_S 0.144` × 屏高/可见世界高 18） | **2.25**（`min(W/LW, H/LH)`） |
| 标题字号 | 72 → 屏幕 187px | 62 → 屏幕 140px |
| 汉字格数 | 28.8 | 25 |
| 点距（屏幕） | 6.48px | 5.63px |
| 点径（屏幕） | 12.2px（可见芯 5.6） | 5.96px（可见芯 5.6） |

**点径这里有个必须算对的换算**：`gl_PointSize = size × (屏高/2) / 距离`，**不含 fov 修正**，
所以世界尺寸推出来的像素直径约为一半。原型 `spotUI(s) = s × tan(fov/2) / UI_S`：
`0.68 × 0.5206 / 0.144 = 2.46 UI px`（不是 4.72）。按世界单位直推会把点径算大一倍，
相邻点重叠 66% —— 那正是"糊成一片光"的来源。

## 运动：为什么"看起来不会动"

三处叠加的错，缺一处都会显得是静止的贴图：

1. **呼吸周期 15 秒**。`sin(t * 0.42)` 的周期是 `2π/0.42 ≈ 15s`，人盯三秒看到的位移
   不到峰值的 4%。改成 `1.36`（4.6s）。
2. **呼吸幅度只有 ±0.8 屏幕 px**。原来是 `2.3 × (breath-0.7)` 世界 px，在 2.25 的缩放
   下等于亚像素。改成按 `scale` 归一化，直接锁到屏幕 ±6px（原型 `calmS=0.07` 时
   骨架呼吸仍有 ~5 屏幕 px）。
3. **只有整片呼吸，没有颗粒级活气**。加一个逐粒子独立相位的微环（屏幕 ±2.4px，
   约点距 42%），点阵才有"沙沙在动"的质感。

实测（每秒累计路程，不是净位移 —— 来回摆动会被净位移抵消掉）：
`3.85 → 14 px/s`；0.7 秒内平均位移 5.02px、最大 9.1px（约一个点距）。

## 交互

- 悬停某个控件 → 云层倾泻进它，同时骨架里属于该控件的点`aHot` 提亮 55%、加粗 10%
- 点击 → 从触点推一圈冲击波（骨架只吃 22%，文字不跟着晃）
- 提交成功 → 点阵与头像环流一起炸开，760ms 后跳 targetURL

### 灌注不能「描出控件外框」

灌注做错时的症状是：鼠标压到任何控件上，都能看到它的外接矩形轮廓。
三个独立原因，缺一个都会出现：

1. **覆盖率必须按整格面积算**。`scanPart` 的扫描区是「控件矩形 ±pad」，
   起点常落在格子中间；若按 `max(x0, 格边界)` 裁掉半格，分母只剩不到 1px，
   边缘 1 个抗锯齿像素就等于 100% 覆盖 → 整列/整行点亮 = 一条竖直的边。
   实测 `hint` 首列曾出现 43 个点（其他列 1~11 个）。
2. **线条类不能用细网格**。线宽 2.4 对细格 1.17 是 2.05 格，阈值怎么调都会
   点亮 2 行。边框/箭头改用**骨架格**取槽位（与骨架点重合，只叠亮度），
   只有面状文字才用细格去填笔画内部的空隙。
3. **线条类不能半格交错**。`off = CELL_R × scale × 0.5 ≈ 3px`，把 5.96px 的点
   压在骨架点旁边，视觉宽度直接撑到 9px。

另外槽位亮度要**按角色分档**：边框在骨架里本就比文字暗一级（`ROLE_A` 0.70 vs 0.88），
灌注时一律提到 1.15 会让它反超文字 —— 那就是「把框描出来」的观感来源。

输入法靠一个透明 `<input>` 收键盘，它的位置/宽度由墨稿实测出来的 `HIT.input` 反推，
右侧让出 34px 给箭头，否则箭头被 input 盖住点不到。

## 认证协议（照抄官方，不能改）

```
GET  /bfl/info/v1/olares-info   → { data: { olaresId, osVersion, avatar } }
GET  /api/state                 → authentication_level === 2 表示已登录
POST /api/firstfactor           → { username, password, keepMeLoggedIn, targetURL }
```

- `osVersion >= 1.12.0` 时 password 要变成 `md5(password + "@Olares2025")`
- 网关认不出用户时报 `Cannot get user name from header` → 带 `X-Bfl-User` 重试一次
- `targetURL` 默认 `https://desktop.<olaresId 的 @ 换成 .>`，有 `?rd=` / `?redirect=` 时以它为准

官方前端注册过 `scope=/` 的 Service Worker，会一直喂旧缓存，所以 `index.html` 里先注销一次；
首次访问仍可能命中旧 SW，需要手动 Clear site data。
