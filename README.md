# Olares 涌现式神经网络 UI · 粒子原型

用 Three.js 粒子群演示 Olares「涌现式 UI」概念：粒子先组成悬浮球体，遥测驱动其呼吸/形变/配色，
唤出时收拢成可交互的粒子界面（标题、输入框、勾选框、按钮），每个控件由点阵粒子构成，鼠标悬停时
增援粒子倾泻到控件上提高密度。

当前基线版本：**v0.14（点阵字体工程）**。

---

## 快速开始

```bash
# 开发版（ES Module + importmap，必须走 http，不能 file:// 打开）
python -m http.server 8765 --directory .
# → http://localhost:8765/index.html

# 单文件版（双击即开，无需服务器；three 与主代码已内联）
node build-standalone.mjs
# → particle-sphere-standalone.html
```

`particle-sphere-standalone.html` 与 `dist/`（验证截图）是构建/验证产物，已加入 `.gitignore`，
随时可用上面的命令重建。

## 当前版本关键参数（v0.14）

调清晰度基本只动这几处，都在 `src/main.js` 顶部附近：

| 参数 | 值 | 含义 / 调它的后果 |
| --- | --- | --- |
| `COUNT` | 7300 | 总粒子 = 骨架 3500 + 增援 3800 |
| `STATIC_N` | 3500 | 骨架粒子数，**应 ≈ 候选槽位数 M**（当前 3462）。1:1 才无叠加、无各向异性拉伸；超过 M 就是 2 倍过采样，会把点阵搅成实心亮带 |
| `SCAN_CELL` | 2.5 | 骨架扫描格边长（UI px）= 点距。汉字点阵可读下限 16×16 格 → 字号 < 40px 必糊 |
| `SCAN_CELL_R` | 1.4 | 增援独立细网格（悬停控件的槽位密度） |
| `SCAN_TH` | 0.45 | 格覆盖率阈值：格内 alpha>90 像素占比 ≥45% 才点亮（亮度不参与几何判定） |
| `UI_TRACK` | 2.5 | 字距 = 1 格（汉字全角默认紧贴，不留缝就并字） |
| `UI_OPS` / `UI_SIZE` | 0.68 / 0.68 | 骨架点不透明度 / 世界尺寸（1:1 无叠加后可提亮） |
| `UI_FONT` | 等线 Light → 雅黑 Light → SimHei | 笔画宽必须 ≈ 1 格。等线 Light 实测 2.0px÷2.5 = 0.8 格；雅黑/黑体 3.0px = 1.2 格 → 横截面恒 2 格，字怀被吃成实心块 |

三条几何原则（v0.14 核心，改任何字号/密度前先过一遍）：
1. **笔画宽 ≈ 1 格**（靠字重 + 零描边；加 2.5px 描边会让笔画变 5px = 2 格）；
2. **字距 ≥ 1 格**；
3. **1 格 1 点、格心对齐**（骨架粒子数 ≈ 槽位数 M，不是越多越清）。

点精灵尺寸公式陷阱：Three 的 `gl_PointSize = size × (屏高/2) ÷ 距机位`，**不含 fov 修正**，
按世界尺寸推算会高估约 2 倍；再叠加软光晕贴图可见芯只有 ~43% → 曾长期把「光斑」当 4px 实际只有 1.6px。
现用硬芯贴图（`glowTexHard`，可见芯 ≈0.88），诊断里的 `spot` 按 `size*tan(fov/2)/UI_S` 计算。

## 深链参数（调试/复现截图用）

基础：`index.html?参数&…`（查询串必须在 `#` 前）

| 参数 | 作用 |
| --- | --- |
| `#sphere/#torus/#galaxy/#wave/#sculpture` | 直达形态 |
| `?ui=1` | 直接落位粒子 UI 面板（不等半径唤出动画） |
| `?uipose=1` | UI 相机直接落位（无头截图首帧可用） |
| `?uitext=demo` | 预填输入框文字（支持中文，需 URL 编码） |
| `?uihover=input\|title\|ok\|cancel\|check0\|check1\|close\|sub` | 强制增援倾泻到指定控件 |
| `?n=7300&static=3500` | 覆盖总粒子数 / 骨架数（上限 16000 / 12000） |
| `?load=0.8&temp=0.92` | 手动工况（自动关遥测） |
| `?breathe=0~1&bp=<弧度>&pose=inhale\|exhale` | 呼吸幅度 / 相位 / 静态极点 |
| `?auto=0&morph=0` | 关自动形态巡航 / 关自动形变 |
| `?t=<秒>` | 初始时间偏移 |
| `?fnt=deng\|yahei\|simhei` | 切换字体（对比笔画宽用） |
| `?th=0.45&track=2.5` | 覆盖覆盖率阈值 / 字距 |
| `?nolink=1` | 关闭 UI 点阵连线 |
| `?ops=&opsd=&dotsz=&dotszd=` | 骨架/增援的不透明度与尺寸 |
| `?hide=S\|D\|*` | 隐藏骨架层 / 增援层 / 全部（分层排障） |
| `?selftest=1` | 同步自检：物理收敛偏差、槽位数、角色分布、呼吸振幅、配色 → 左上角面板 |

## 验证方法

- **自检**：`?selftest=1&ui=1&uipose=1`，读 DOM `#selftest`。当前基线：骨架收敛偏差 1.1px、
  槽位 3462 vs 骨架 3500、点距/光斑 1.42（约 30% 暗缝）、倾泻 3800/3800、零报错。
- **无头截图**：Chrome 在用户浏览器已运行时，`--headless --screenshot` 会被**静默委派**给该实例
  （exit 0、零输出、无水花）。改用 `--remote-debugging-port=9224` + 独立 `--user-data-dir`，
  再用 CDP 驱动，页面按真实时间跑、rAF 正常推进（可验证收敛全过程，不只首帧）。
- **细节放大**：`crop.html?src=<png>&x=&y=&w=&h=&s=4` 把截图局部放大后截图，判断点阵是否可辨。

## 版本管理约定

每完成一版（自检通过 + 截图复查）：

```bash
git add -A
git commit -m "v0.15: <一句话主题>"
git tag -a v0.15 -m "<这一版解决了什么>"
```

回到某一版：

```bash
git log --oneline              # 看历史
git tag                        # 列所有版本
git checkout v0.14             # 切到该版（分离 HEAD，只读查看）
git switch -                   # 切回最新
git checkout v0.14 -- src      # 只把某一版源码拉回来（推荐，用于回退效果）
npm run build                  # 单文件版不入库，回退后需重建
```

`particle-sphere-standalone.html`、`dist/`（截图）、`.tmp/`（字体探针 / CDP 驱动）都不入库：
它们是可重建产物，避免每个版本把几百 KB 的生成文件和几十张 PNG 塞进历史。

## 已知限制

- 无头软渲染下 fps 只有 14~17（SwiftShader），不代表真机；真机 Chrome 稳定 60fps。
- 悬停切换 / 拖尾彗光 / 打字重采样需要真实鼠标键盘，无头只能覆盖深链落位态。
- 输入框聚焦打字时若鼠标不在输入框上，增援不会跟着文字走（静态骨架显示文字，可接受）。
- 遥测为模拟数据（正弦 + 噪声），尚未接 Olares Prometheus 真实接口。
