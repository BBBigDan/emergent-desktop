# agent 能力路线图（2026-10-29）

> 现状：**38 个工具**，读系统（olares CLI 全家桶）、文件、屏幕（粒子层 / 画布 / 出图）、
> 记忆、造工具都通。短板不在"会做什么"，在**三个维度**：
> ① 时间（不会到点自己动、不会主动开口）② 输入（看不懂你发的图和文档）
> ③ 对立视角（单次回复里没法真的站到反面，于是给和稀泥的答案）。

每条都写四件事：**用户会怎么感受到它缺** / **最小可行形态** / **判据** / **代价与风险**。
不写"什么时候做"，只写"做的话长什么样"，避免变成愿望清单。

---

## ① 定时与主动：让它替你盯着

**症状**：说"每小时看一眼 n8n 还在不在重启""每天早上把磁盘和备份报一下"，只能现在查一次。

**现状证据**：全仓 grep `cron|schedule` 只命中 `scheduleSave`（会话落盘）和 SSE 心跳；
85 处 `emit()` 全部发生在某一轮对话内部 —— 页面关了就没有任何东西能叫醒它。

**最小形态**
- 工具 `schedule`：`{ every: '15m' | '1h' | 'daily@08:00', task, tools?: [...] }`，落 `state/<user>/tasks.json`
- 服务端一分钟一次 tick；命中即**自动开一轮**（同一个 sid，标 `auto: true`）
- 结果落会话，前端置"未读"；同一任务连续 N 次结论相同 → 降频（防刷屏）
- 前端：状态条上一个极小的时间刻度，有未读时才亮

**判据**：用户句子里有"每隔 / 每天 / 定时 / 一直盯着 / 一有变化就"。

**代价与风险（这条最难的不是定时，是授权）**
- `APPROVAL_MS=90s` 超时按拒绝 —— 用户不在跟前，**任何 danger 操作永远过不去**。
  所以必须先有"该任务预授权哪些工具"，否则定时任务只能查不能改。
- 无人值守时的写入是不可逆的：预授权只允许**白名单 + 幂等**操作（重启 / 清缓存行，
  不许 删除 / 卸载）。第一次必须由用户在当场点过一次"以后这类也允许"。

**验收**：设一个"每 5 分钟看 n8n 重启次数"，四次结果自动落会话；
关掉页面再打开能看到未读；中途 pod 重启，心跳断一次后自己接上。

## ② 看得懂图与文档

**症状**：丢一张报错截图它读不了。`fs_read` 的原文是"二进制会如实拒绝"。
它刚学会**画**图，却看不懂你发的图 —— 这个不对称最刺眼。

**最小形态**
- `fs_view`：图片 → 视觉模型（`{ path | url, question }`），返回文字描述/回答
- `fs_extract`：PDF / docx / xlsx → 纯文本（零依赖可做，先只 PDF 抽文本 + 表格降级为文本）
- 两者都走和 `fs_read` 一样的大小上限（图片缩到长边 1568 再上传，省钱）

**判据**：用户给了路径且扩展名是图片/文档，或者句子里有"这张图 / 这个文件 / 这份账单 / 帮我看看截图"。

**代价**：`fs_view` 需要**能看图的模型**。现在的本地 7B 多半没有视觉；
接外部视觉接口 = 另一个 key、另一份账单。所以这条要先问：**这台机器上用哪个模型看图**。

**验收**：丢一张 Olares 报错截图，它能说出"哪个应用、什么错、下一步点哪"。

## ③ 应用层写操作（只读变能改）

**症状**：说"把那个正在下的种子停掉"，它能告诉你 qBittorrent 在跑，但停不了。

**现状**：`olares_act` 覆盖的是**系统层**（装/停/重启/升级应用）；`web_get` 只有 GET、只有纯文本，
还主动挡掉 `*.svc` / `*.internal`。应用内部（Jellyfin 加用户、qb 加种子、n8n 改流程）是空白。

**最小形态**：不做"通用网页操作"，做**按应用接 API 的适配器**，一次一个：
- `app_api` 工具 + `agent/apps/<app>.mjs`（每个文件声明：baseURL 怎么拼、认证从哪来、有哪些 op）
- 先接 qBittorrent（停/加种子、看进度）和 Jellyfin（用户、会话）—— 这两个最常用、API 最稳
- 认证从 Secret 来，**不许模型经手凭据**

**判据**：用户要改的东西在某个具体应用里，而 CLI 没有对应命令。

**代价**：每个应用一套认证、一套字段，应用升级就破。所以**按需接**，不做全覆盖；
每个适配器配一份"录放夹具"（像 `fixtures/olares/`），否则接口一改只能靠线上复现。

**验收**：一句话停掉一个真在下的种子，qb 里确认停了。

## ④ 从"你纠正过它"里学

**症状**：你说"不对，是另一个"，它当场改；下次同类问题还犯。

**原因**：抽取器抽的是**事实**（"这台机器装了 n8n"），不抽**判断错误**
（"它把 Jellyfin 当成了 Navidrome"）。纠正信息根本没进记忆。

**最小形态**：纠正发生时（同一轮里用户紧接着否定前一条回答），记一条**错题**：
`{ 场景关键词, 它当时怎么判断的, 正确是什么 }`，进独立的 `mistakes` 命名空间；
`memory_recall` 命中场景时把错题排在最前面（带"上次这里判断错过"的标签）。

**判据**：用户紧接着说"不对 / 不是 / 我说的是" —— 这条信号很硬，不需要模型自省。

**代价**：错题也会过期（环境变了，当年的教训变成误导）。每条带时间戳和"被推翻"标记；
命中两次都对不上就降权。

**验收**：故意让它认错一个应用，再问同类问题，它自己避开那个错。

## ⑤ 子 agent：**不是为了并行，是为了"不许和稀泥"**

用户原话（2026-10-29）：

> 有一种情况是必须要使用子 agent 的，就是执行的生成中，或者任务中，有互相冲突的内容或者角色，
> 模型没有办法在一次回复中换对立角度思考，必然会因为梯度下降而陷入无意义的不出错回复。

这条是**结构问题，不是提示词问题**。在同一个上下文里让它"先支持再反对"，它会在采样时
用"另一方面""这取决于你的需求"把两个立场中和掉 —— 因为那是训练分布里"安全"的那一侧。
**换一个上下文，立场才能被锁住。**

**必须用子 agent 的判据**（可判定，不靠模型自省）

1. **决策类**：「该不该 / 要不要 / 哪个更好 / A 还是 B / 值不值得」——要表态，不许罗列
2. **冲突目标**：同一任务同时要"省钱 + 稳定""快 + 全""安全 + 方便" —— 单上下文给的折中往往两边都不满足
3. **多角色 / 立场**：评审自己写的代码、审自己的方案、写"支持 vs 反对"、模拟用户投诉、红队
4. **自审**：`tool_write` 写完、长结论给出之前 —— 现在**完全没有 review 环节**
5. （附带好处，不是必须理由）互相独立的子任务可以并行

**不该用的判据**（一次子 agent = 一份完整上下文，别滥用）
事实查询（"装了哪些应用"）、单点写操作、指令已经明确到无需判断的执行。

**形态**
- `agent/sub.mjs`：`runSub({ role, task, stance, budget })` —— 独立 messages，
  system 只含**该角色 + 工具子集 + 输出格式**（不许塞 9.7k 的"场说明书"）
- 工具 `sub_run`（safe）：`role ∈ advocate | critic | verify | explore | redteam`
- 返回**固定形状**，强制不许中和：
  `{ stance, conclusion, reasons[≤3], strongest_counter, confidence, evidence[] }`
  —— `strongest_counter` 是"对方最强的攻击点**由我来替他提出**"，比"我既…又…"诚实
- 工具 `sub_panel`（决策类）：一次起 2~3 个对立角色，主 agent 只做**裁决**
- **主 agent 不许把两个对立结论"综合"成折中。必须选一个，并说明放弃的代价。**
- 硬约束：**不许嵌套**（子 agent 不能再起子 agent）、默认 6 步 / 5 分钟、
  看不到主对话（只看到 task 文本）—— 否则立场会被污染
- 可见性：子 agent 说了什么要能展开看（进 trace），否则决策成了黑箱

**代价**：一次决策 = 2~3 份上下文（9k 起）+ 各自若干步。所以判据要卡住，
不能"每次思考都开三个会"。

**验收（A/B，同一个问题问两遍）**
- 题：**「这台机器该不该常驻 ComfyUI」**（真有两面：占 6 核 7Gi vs 随时能画）
- 现在：会得到一段"各有优劣"的回复
- 之后：明确结论 + 采纳谁的理由 + 放弃的代价；`sub_panel` 的两份原文可展开

## 顺序与依赖

```
⑤ 子 agent ──┬─→ ④ 从纠错里学（自审本身就要一个"反方"来看错题）
             └─→ ① 定时（无人值守的结论更该被审）
② 看图/文档 ──→ ③ 应用写操作（改之前先看懂界面截图，常常是必需的）
```

- **先做 ⑤**：它不改任何外部接口、纯内部结构，能立刻改善**回答质量**（不需要新依赖、不需要 key）
- ② 卡在"用哪个模型看图"，要先定
- ① 卡在授权模型（预授权白名单），要比 ⑤ 想得更久
- ③ 是最重的（每个应用一份适配器 + 夹具），按需一个个来

## 已否掉的路（别再讨论）

- **让模型自己写 ComfyUI workflow**：7B 写不对 2KB 的节点连线，且"任意图"= "任意节点执行"。
  图归服务端，模型只填槽位。（已落地）
- **通用网页点击自动化**（浏览器驱动）：这台机器没桌面、每个应用一套登录，
  维护成本远高于按应用接 API。
- **把步数上限调大来"让它想得更久"**：判据错在"次数"，应该在"有没有进展"。（已落地）
