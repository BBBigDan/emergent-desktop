# agent 能力路线图（2026-10-29）

> 现状：**38 个工具**，读系统（olares CLI 全家桶）、文件、屏幕（粒子层 / 画布 / 出图）、
> 记忆、造工具都通。短板不在"会做什么"，在**三个维度**：
> ① 时间（不会到点自己动、不会主动开口）② 输入（看不懂你发的图和文档）
> ③ 对立视角（单次回复里没法真的站到反面，于是给和稀泥的答案）。

每条都写四件事：**用户会怎么感受到它缺** / **最小可行形态** / **判据** / **代价与风险**。
不写"什么时候做"，只写"做的话长什么样"，避免变成愿望清单。

---

## ① 定时与主动：让它替你盯着

**症状**：说"每小时看一眼 n8n 还在不在重启""每天早上把磁盘和备份报一下"，只能现在查一次。

**现状证据**：全仓 grep `cron|schedule` 只命中 `scheduleSave`（会话落盘）和 SSE 心跳；
85 处 `emit()` 全部发生在某一轮对话内部 —— 页面关了就没有任何东西能叫醒它。

**最小形态**
- 工具 `schedule`：`{ every: '15m' | '1h' | 'daily@08:00', task, tools?: [...] }`，落 `state/<user>/tasks.json`
- 服务端一分钟一次 tick；命中即**自动开一轮**（同一个 sid，标 `auto: true`）
- 结果落会话，前端置"未读"；同一任务连续 N 次结论相同 → 降频（防刷屏）
- 前端：状态条上一个极小的时间刻度，有未读时才亮

**判据**：用户句子里有"每隔 / 每天 / 定时 / 一直盯着 / 一有变化就"。

**代价与风险（这条最难的不是定时，是授权）**
- `APPROVAL_MS=90s` 超时按拒绝 —— 用户不在跟前，**任何 danger 操作永远过不去**。
  所以必须先有"该任务预授权哪些工具"，否则定时任务只能查不能改。
- 无人值守时的写入是不可逆的：预授权只允许**白名单 + 幂等**操作（重启 / 清缓存行，
  不许 删除 / 卸载）。第一次必须由用户在当场点过一次"以后这类也允许"。

**验收**：设一个"每 5 分钟看 n8n 重启次数"，四次结果自动落会话；
关掉页面再打开能看到未读；中途 pod 重启，心跳断一次后自己接上。

**已落地（2026-10-30）**：`agent/sched.mjs`（时间算术，能脱离服务测）+ `schedule` 工具
（`op=add|list|cancel|pause|resume`）+ `server.mjs` 里的 tick 与自动回合。
真正拦住这条的**不是定时器，是授权**，所以落地的形状是：

- **定时回合只发 safe 工具，执行层再挡一道。** 没人在跟前，审批门等 90 秒后按拒绝，
  用户第二天看到的是"它卡了半个晚上"。所以 danger/confirm 的工具在 auto 回合里
  **根本不进工具表**，模型硬调也被立刻拒（理由说成"没人在跟前"，不是"工具坏了"）。
  代价：定时任务**永远不能改系统** —— 预授权白名单还没解决，就不许写入。
- **补跑只补一次。** 过期的任务（pod 重启、整夜没跑）醒来只跑一遍，然后从 now 重排；
  按周期逐条补会让人睁眼收到一串一模一样的结论。
- **结论一样就放大间隔（×2，上限 ×8），不是静音。** 没变化时说没变化；
  一有变化立刻恢复原频率。降频不改 `everyMs`，只放大 `factor`，用户还看得见原始频率。
- **忙就跳过，不排队。** 排队会让"每 5 分钟"在一次长任务之后连喷四次。
- **连错 5 次自动暂停。** 最坏的形态是每 30 秒失败一次、永远不停：日志满了、账单也满了。
- **`/new` 时任务跟着搬过去。** 不搬的话结论一直落进归档的那段会话 ——
  用户开着新对话等一晚上，什么都没收到，而任务其实准时跑了。
- 前端：状态条最右**最多 4 根刻度**（有未读才亮，清单在 tooltip 里）。
  刻度用粒子画，单独一页 `shell/test-agentbar.html?n=4&unread=1` 供眼睛验收。

**还没解决的**：预授权的"以后这类也允许"（第一次必须有人在场点过一次）；
主动开口（现在只会回答，不会因为"发现异常"自己起话头）。

## ② 看得懂图与文档

**症状**：丢一张报错截图它读不了。`fs_read` 的原文是"二进制会如实拒绝"。
它刚学会**画**图，却看不懂你发的图 —— 这个不对称最刺眼。

**已落地（2026-10-30）**

拆成两半，因为它们的门槛根本不同：

| 能力 | 靠什么 | 谁的模型都能用吗 |
|---|---|---|
| `fs_extract`：pdf / docx / xlsx / pptx / html / 文本 → 字 | 零依赖手写解析（zip + FlateDecode + 文本算子） | **是**，和模型无关 |
| `fs_view`：图片交给模型看 | 模型的视觉能力 | 只有**看得见**的模型 |

顺序是**代价问题不是风格问题**：一份 20 页 PDF 渲染成 20 张图是几万 token，
而"违约金多少"只需要其中的字。所以：有字先抽字，抽不到（扫描件 / CID 编码）
才看图；照片截图直接看图。

**视觉能力：查资料，不试。**（2026-10-30 被用户纠正）

第一版做成了"发一张 8×8 小红图去试探"，用户当场否掉：

> 「模型支不支持多模态都是公开的信息，不需要你在这里做试验」

他是对的。查一下就知道：**DeepSeek-V4.1-Flash 原生多模态**（模型卡：多模态 MoE +
DeepSeek-ViT 视觉编码器，图像与文本一起进、文本出；ModelScope 标签是"视觉多模态理解"）。
也就是说默认模型本来就能看图，压根不用另配视觉模型 —— 而我去发请求试了一遍，
试出个 402 还差点得出"不知道"。

所以能力是**表里的一列**（`models.mjs` 的 `vision` + `visionSrc` 出处），
和 `think` / `tools` 同一性质：

- 平台模型：手写，`visionSrc` 记出处（模型卡 / 厂商文档）。
- 本地模型：Ollama `/api/show` 自报的 `capabilities`（模型自己声明的）。
- 自定义网关：公开资料管不到别人家的中转站 → `null`（不知道），**照发**。
- 三种值：`true` / `false` / **`null`**。查得到就写死，查不到才写 `?`。

**观测只作兜底，且不花额外请求**：真发图被接口 400 / 它自己回"我看不到图片"，
把结论记进 `config/vision.json`（7 天过期），并把历史里的图换成一句文字
（否则**每一步**都多一次失败请求）。`POST /api/models/vision` 保留，但只服务于
一个显式动作：**你怀疑网关把图丢了**（公开说能看、实际说看不到）时手动核一次。
一次成功发图**不会被记成"能看"** —— 网关可能悄悄丢图而照样回 200。

**落地的边界**
- 图**不进工具结果**（OpenAI 形状里工具消息只能是字符串）→ 工具回"看过了"，
  紧接着补一条带图的 `user` 消息。这是唯一的"结构上的谎"，所以文字里写明"这是你刚打开的图"。
- 图**也不进上下文正文**：base64 一个字都不回灌，回灌的是尺寸和 MIME。
- 前端同时把图摆到屏幕上（`/api/fs/img`，复用图片面板）：用户得知道**它在看哪张图**，
  否则它说"图里是猫"，用户没法判断它在胡编。
- 图 > 3MB 直接拒（没有解码器就没法缩图），如实说"先缩一下"。

**已知没做**
- OCR。扫描件只能靠视觉模型，没有视觉就只能说"抽不到字"。
- 缩图。要解码器（png/jpeg 解码 + 重采样），是另一个依赖；现在是大图直接拒绝。
- PDF 的 CID / Identity-H 中文：没有 ToUnicode 表解析，抽不出来时**明确说抽不出来**
  （返回半篇乱码比空更坏 —— 模型会把乱码当正文引用）。

**验收**：丢一张报错截图，它说出"哪个应用、什么错"；丢一份 PDF 合同，它答出违约金
（且用 `fs_extract` 而不是看图）；换一个看不了图的模型，它**明说看不了**，不猜。

## ③ 应用层写操作（只读变能改）

**症状**：说"把那个正在下的种子停掉"，它能告诉你 qBittorrent 在跑，但停不了。

**现状**：`olares_act` 覆盖的是**系统层**（装/停/重启/升级应用）；`web_get` 只有 GET、只有纯文本，
还主动挡掉 `*.svc` / `*.internal`。应用内部（Jellyfin 加用户、qb 加种子、n8n 改流程）是空白。

**最小形态（2026-10-30 改）**：**不做按应用写适配器。** 用户当场否掉了原方案：

> 「能做通用的吗？如果给每个应用都单独写的话这个需求就爆炸了」

他是对的。原方案错在把"通用"理解成"通用到网页点点点"—— 被否掉的是**浏览器自动化**，
不是"通用"这件事本身。真正该通用的是三件事，而它们和应用无关：
地址（应用在哪）、认证（四种形态）、发请求（拼 URL / 限时 / 限体积 / 切形状）。

**落地形态**：`agent/apps.mjs` + 两个工具（读 `app_api` / 写 `app_act`），
外加 `agent/config/apps/<name>.json` 一行描述（`probe` 现探，或用户手写）。

**判据**：用户要改的东西在某个具体应用里，而 CLI 没有对应命令。

**代价（新方案的）**：
- 认证只有四种形态（none / header token / Basic / 表单换票）。第五种（OAuth 设备码、
  mTLS）就得写代码 —— 到那时再说，别提前抽象。
- `probe` 能自动找 OpenAPI 和登录端点，但**不能替你猜密码**：凭据必须用户在 Secret 里配。
- 应用升级改了路径 → 坏掉的是那一行描述，不是整个适配器（这是它比"一个应用一个 .mjs"好的地方）。

**验收**：一句话停掉一个真在下的种子，qb 里确认停了。

**已落地（2026-10-30）**：见下面"③ 落地细节"。

## ④ 从"你纠正过它"里学

**症状**：你说"不对，是另一个"，它当场改；下次同类问题还犯。

**原因**：抽取器抽的是**事实**（"这台机器装了 n8n"），不抽**判断错误**
（"它把 Jellyfin 当成了 Navidrome"）。纠正信息根本没进记忆。

**最小形态**：纠正发生时（同一轮里用户紧接着否定前一条回答），记一条**错题**：
`{ 场景关键词, 它当时怎么判断的, 正确是什么 }`，进独立的 `mistakes` 命名空间；
`memory_recall` 命中场景时把错题排在最前面（带"上次这里判断错过"的标签）。

**判据**：用户紧接着说"不对 / 不是 / 我说的是" —— 这条信号很硬，不需要模型自省。

**代价**：错题也会过期（环境变了，当年的教训变成误导）。每条带时间戳和"被推翻"标记；
命中两次都对不上就降权。

**验收**：故意让它认错一个应用，再问同类问题，它自己避开那个错。

**已落地（2026-10-30）**：`agent/mistakes.mjs`（判据 + 存储 + 命中）+ server 两处接线
（记在回合开始、注入在 `ctxNote` 最前面）。三个刻意的决定：

- **判据是句式，不是自省。** 只认"不对 / 我说的是 / 你弄错了 / 纠正一下"打头的句子，
  而且**必须有上一轮真的说过话**（没有上一句时，"不对"可能在否定别的东西，
  记下来就是一条假错题 —— 假错题每轮都跳出来道歉，比不记更糟）。
  反例钉住了：「不是所有应用都在跑」「这样不对吧，我觉得再等等」都不算纠正。
- **记原话，不记总结。** `wrong` = 它上一轮说的那句，`right` = 用户纠正的原话。
  让 7B 总结"我错在哪"，它会写成"我需要更仔细地确认信息"——那种话进上下文只会让它更啰嗦。
- **命中靠具体名字，不靠语气相似。** 场景词只抽拉丁词、引号里的中文、纯数字
  （端口号是唯一能把"同一个场景的两个不同坑"分开的东西）。中文两字随便撞会让错题
  在无关问题里冒出来 —— 那种"提醒"只是在添乱。
- **会过期**：90 天前的错题不再注入；同场景最多留 3 条；换个说法说同一个坑只加重
  （`repeat`，提示里说"这个坑踩过两次"比说一次更有分量）。
- 存 `agent/config/mistakes.json`，**不塞进记忆图**：错题的检索方式（按名字命中、排最前）
  和事实不一样，混在一起会被降级成一条普通记忆，而它必须在每次同类提问里优先出现。
  `memory_recall` 把它放在 `mistakes` 字段里先回，实现失败时也不影响记忆那条路。

**没做的**：错题只喂给"同一句话"，不主动告诉用户"我记住了"（只在观察窗留一行
「记下了这条纠正」）；也不会跨会话地自我复盘 —— 那需要第五层的巩固，属于记忆那块的事。

## ⑤ 子 agent：**不是为了并行，是为了"不许和稀泥"**

用户原话（2026-10-29）：

> 有一种情况是必须要使用子 agent 的，就是执行的生成中，或者任务中，有互相冲突的内容或者角色，
> 模型没有办法在一次回复中换对立角度思考，必然会因为梯度下降而陷入无意义的不出错回复。

这条是**结构问题，不是提示词问题**。在同一个上下文里让它"先支持再反对"，它会在采样时
用"另一方面""这取决于你的需求"把两个立场中和掉 —— 因为那是训练分布里"安全"的那一侧。
**换一个上下文，立场才能被锁住。**

**必须用子 agent 的判据**（可判定，不靠模型自省）

1. **决策类**：「该不该 / 要不要 / 哪个更好 / A 还是 B / 值不值得」——要表态，不许罗列
2. **冲突目标**：同一任务同时要"省钱 + 稳定""快 + 全""安全 + 方便" —— 单上下文给的折中往往两边都不满足
3. **多角色 / 立场**：评审自己写的代码、审自己的方案、写"支持 vs 反对"、模拟用户投诉、红队
4. **自审**：`tool_write` 写完、长结论给出之前 —— 现在**完全没有 review 环节**
5. （附带好处，不是必须理由）互相独立的子任务可以并行

**不该用的判据**（一次子 agent = 一份完整上下文，别滥用）
事实查询（"装了哪些应用"）、单点写操作、指令已经明确到无需判断的执行。

**形态**
- `agent/sub.mjs`：`runSub({ role, task, stance, budget })` —— 独立 messages，
  system 只含**该角色 + 工具子集 + 输出格式**（不许塞 9.7k 的"场说明书"）
- 工具 `sub_run`（safe）：`role ∈ advocate | critic | verify | explore | redteam`
- 返回**固定形状**，强制不许中和：
  `{ stance, conclusion, reasons[≤3], strongest_counter, confidence, evidence[] }`
  —— `strongest_counter` 是"对方最强的攻击点**由我来替他提出**"，比"我既…又…"诚实
- 工具 `sub_panel`（决策类）：一次起 2~3 个对立角色，主 agent 只做**裁决**
- **主 agent 不许把两个对立结论"综合"成折中。必须选一个，并说明放弃的代价。**
- 硬约束：**不许嵌套**（子 agent 不能再起子 agent）、默认 6 步 / 5 分钟、
  看不到主对话（只看到 task 文本）—— 否则立场会被污染
- 可见性：子 agent 说了什么要能展开看（进 trace），否则决策成了黑箱

**代价**：一次决策 = 2~3 份上下文（9k 起）+ 各自若干步。所以判据要卡住，
不能"每次思考都开三个会"。

**已落地（2026-10-29 夜）**：`sub_run`（critic / advocate / character）+ **`dialogue`**。
后者的关键设计是**卡片不出服务端**：角色卡（要什么/怕什么/筹码）只在服务端生成和消耗，
主模型只拿到一段拼好的 `名字：台词`。7B 实测会三次以不同方式泄漏元信息
（卡片字段被念成台词 → 格式说明被抄进正文 → 数组结构照抄上屏），**换格式修不完**。
弱模型的结论：管道能修，**人物保持是模型能力**，换结构救不了。

**验收（A/B，同一个问题问两遍）**
- 题：**「这台机器该不该常驻 ComfyUI」**（真有两面：占 6 核 7Gi vs 随时能画）
- 现在：会得到一段"各有优劣"的回复
- 之后：明确结论 + 采纳谁的理由 + 放弃的代价；`sub_panel` 的两份原文可展开

## 顺序与依赖

```
⑤ 子 agent ──┬─→ ④ 从纠错里学（自审本身就要一个"反方"来看错题）
             └─→ ① 定时（无人值守的结论更该被审）
② 看图/文档 ──→ ③ 应用写操作（改之前先看懂界面截图，常常是必需的）
```

- **先做 ⑤**：它不改任何外部接口、纯内部结构，能立刻改善**回答质量**（不需要新依赖、不需要 key）
- ② 卡在"用哪个模型看图"，要先定
- ① 卡在授权模型（预授权白名单），要比 ⑤ 想得更久
- ③ 原以为"最重"（每个应用一份适配器），改成通用执行器之后变轻了：**一个模块盖住所有应用**

## ③ 落地细节（2026-10-30）

`agent/apps.mjs` 三件事，都不含应用名：

| 层 | 做法 | 换一个应用要改什么 |
|---|---|---|
| 地址 | 描述文件 → `APP_<名字>_URL` → 同命名空间 DNS | 加一个环境变量 |
| 认证 | none / header token / Basic / 表单换票（cookie 或 JSON 字段） | 描述里写一行 |
| 发请求 | 拼 URL、15s 超时、256KB 上限、JSON 压缩 / HTML 剥标签 | 不改 |

`probe` 是"接一个新应用"的全部工作量：**先找 OpenAPI**（6 个常见路径），
没有就只看登录端点在不在（**只探不用** —— 试错密码会把账号锁掉），
最后拿这份描述**真跑一次只读 GET**，通了才落盘。一份错的描述比没有描述更坏。

两条硬边界（不是建议）：
- **凭据不进模型**：token/密码只从 Secret 读，模型传的 header 覆盖不了 `Authorization` / `cookie`。
- **不许当通用代理**：path 只能是相对路径，`http://` 绝对地址、`//evil` 协议相对、
  元数据地址、kube-apiserver（6443）全部拒。

`app_api`（GET，safe）和 `app_act`（写，danger）**分成两个工具** —— 审批门是按工具名判 level，
一个工具两种危险等级做不到。

## 已否掉的路（别再讨论）

- **让模型自己写 ComfyUI workflow**：7B 写不对 2KB 的节点连线，且"任意图"= "任意节点执行"。
  图归服务端，模型只填槽位。（已落地）
- **通用网页点击自动化**（浏览器驱动）：这台机器没桌面、每个应用一套登录，
  维护成本远高于按应用接 API。
  注意这条否的是**浏览器自动化**，不是"通用"：应用自己有 HTTP API，走 API 才是通用那条路。
- **每个应用写一个 `.mjs` 适配器**：用户否过（"需求就爆炸了"）。一个应用一份代码，
  等于把"接应用"变成"我每周给它写插件"。改成一行描述 + 一个执行器。
- **把步数上限调大来"让它想得更久"**：判据错在"次数"，应该在"有没有进展"。（已落地）
