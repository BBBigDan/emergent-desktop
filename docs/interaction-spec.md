# 交互规格 v1（定稿 2026-10-22）

> 这份文件是**验收基准**，不是设计随笔。改代码之前先改这里；每条都能对着屏幕量。
> 基准分辨率 1440 × 900，坐标单位 px。所有角度用屏幕坐标（y 向下，0° = 正右，顺时针为正）。

## 0. 三句话

1. 屏幕只有三层：**状态区**（它是谁、在想什么）、**内容区**（它说什么）、**输入行**（我要说）。
2. 内容区有两种态，由"有没有答案"决定：没答案时场景占满，有答案时左右各半。
3. **方位即语义**：环形选项的左 = 过去、下 = 现在、右 = 未来。

| 区域 | 位置 | 尺寸 | 常驻 |
|---|---|---|---|
| 状态区 | x 40–1400，y 20–56 | 1360 × 36 | 是，进 agent 就出现 |
| 内容区 | x 40–1400，y 68–760 | 1360 × 692 | 是 |

### 1.2 换题要清场

**新问题提交时，右边那一屏必须先散掉**（`turn` 的 ask 分支 + `submit`，两处都调 `scene.clear()`）。

用户的原话：「右边的场在不需要的时候应该刷掉，它现在始终停留在上一次修改的状态」。
问题换了、答案清了，右边还挂着上一题的仪表和曲线 —— 读起来像"它没听见我在问新的"。

三条约束：

1. **走溶解，不硬切**：`clear()` 是 `transition(空场, outMs=0.8×TIMING.out)`。一整屏仪表在一帧里消失，观感是"闪了一下"。
2. **手势不清**：拖仪表、敲曲线是同一屏之内的操作，散掉等于把用户刚动过的东西收走。
3. **溶解中仍算"有场"**（`hasScene()` 含 `busy`）：否则清场那一瞬间答案会从半幅跳回满宽，再跳回来。

**这条以前不生效的真正原因**：`scene.step()` 全工程没有一处调用 —— 溶解时钟只存在 `this.tr` 里，没人推进它。现在由 deskagent 的 `tick()` 驱动（同时驱动状态条的呼吸）。

### 1.1 输入行的光环

输入行本身是**透明的**（中文输入法的候选框必须挂在真 caret 上），所以屏幕上没有任何东西告诉用户"话该往哪儿说"。所以输入行外面有一圈粒子：

| 项 | 值 |
|---|---|
| 形状 | 椭圆，中心 (720, `lineY − 6`)，rx 316 / ry 32 |
| 粒子 | 420 颗，点距 ≈3.2，点径 1.9 |
| 底光 | 亮度 0.05~0.21（很淡） |
| 流 | 三处亮头沿周长跑，周期 7.7s / 10.5s / 14s；尾巴按距离衰减到 0.16 |
| 径向抖动 | ±2.4px（固定种子）—— 这一条是"粒子流"和"虚线边框"的分界线 |
| 呼吸 | ±1.4px，按屏幕坐标采低频正弦，和骨架同源 |

三条为什么：

1. **不能是静态描边**。均匀亮度的闭合环读成"一个框"，那就等于把 DOM 边框又加回来了 —— 而这套界面的前提是"UI 本身就是粒子"。所以环上必须有速度快慢不一的亮头，底部只留一点底光。
2. **不能用圆角矩形**。椭圆没有四个角，而"角"正是"框"的语感来源。
3. **按弧长均分，不按角度**。椭圆长轴 316、短轴 32，按角度采样会让长轴两端的密度是中间的三倍 —— 两坨挤在一起，中间断成一截一截。所以先建弧长表（720 段），再按弧长等分。

聚焦时整圈亮一档（`hot 0.55`），回车的那一下亮到 1 然后 420ms 内落回 —— 它替"话发出去了"说话，比任何 toast 都轻。

## 2. 粒子池：56000

- 场的粒子总数 `N = 56000`。桌面球面仍只用前 `SPHERE_N = 6400` 颗，观感不变。
- **进 agent 时球面整批退场**：不绘制（alpha → 0）、不跑球面弹簧。那 6400 颗转为 UI 池的一部分。
- 退场/归位都是 **700ms 过渡**，不做一帧切换（五万多颗同时归位会抖）。
- 实测依据：`stepShape` 对 6400 颗耗时 0.172 ms，即约 0.027 µs/颗；56000 颗约 1.5 ms，占 60fps 帧预算 9%。
- 槽位到粒子的映射：`i = (slot * 7919 + 13) % N`（7919 与 56000 互质，双射成立）。
- **为什么从 32000 涨到 56000**：见 §2.1。这个数是"字能读"倒推出来的，不是拍的。

### 2.1 每字 90 颗：可读密度的实测线

字模采样是"按网格取质心"，网格边长 `cell` 由"每字点数预算"逼出来 —— 预算越小，格子越大。实测（20px、DengXian Light、weight 500）：

| 每字预算 | 挣出来的 cell | 笔画(1.3px) ÷ cell | 观感 |
|---|---|---|---|
| 40（旧默认 `size×2`） | 2.55px | 0.51 | **碎渣**：笔画落不到格子上，整行像被描了两遍边 |
| 64 | 2.01px | 0.65 | 勉强，长句仍糊 |
| 90 | 1.70px | 0.76 | **能读**，一眼扫过去不费劲 |
| 112 | 1.52px | 0.86 | 更清楚，但贵 |

所以"可读"的门槛是 **≈90 颗/汉字**，`cell ≈ size × 0.085`。注意这个数**与字号无关**：cell 和笔画都随字号线性放大，点数只取决于 `cell/size` 这个比值。所以 `glyphBudget` 不能用 `size×2`（那让 20px 只有 40 颗、32px 有 64 颗 —— 小字必糊、大字浪费）。

两种密度并存，由调用方显式选：

- `glyphBudget(size)` → `size×2`：**装饰性**文字（场景里的轴标、角标），读得出大概即可。
- `glyphBudget(size, true)` → `size×4.5`（56~200）：**要读**的文字（答案、问句、场景里的 CJK 标签）。

代价：56000 − 问 800 − 表情 300 = 54900，答案 320 字 ×90 = 28800，剩 26100 给场景。这是 §9 全部数字的来处。

## 3. 状态区（粒子，左上角）

一行，13px 粒子字，y = 38（和 DOM 那一行同一基线），常驻。**字是粒子画的**（`agentbar.js`），DOM 只留悬停区与 tooltip。

| 项 | 形态 | 语汇 |
|---|---|---|
| 连接 | 14 颗围成的小点，呼吸 0.55~1.0 | 青=通 / 琥珀=在想 / 红=断（断线时不呼吸） |
| 模型 | 13px 粒子字，超 18 字截断加 `…` | 去掉 org 前缀（`Qwen2.5-7B-Instruct`） |
| 上下文 | **点阵水位线** 96px / 48 颗 + 数字 `12.4k/32.8k` | 左亮右暗，≥75% 转琥珀 |
| 记忆 | `16 条` | 只有一个汉字 |

三条约束：

1. **13px 是这套点阵的下限**，而汉字在这个字号会糊（`cell`≈1.7px，笔画 0.9px，比值 0.53）。所以整行只放**一个**汉字（"条"），其余全是拉丁和数字 —— 换成"上下文 12.4k"实测糊成一片，不是字号问题，是笔画问题。
2. **水位线的已用/未用必须分两批写**：`slotPut` 的亮度是整批一个 `scl`，而 `ink` 的映射是 `0.55+0.45×ink` —— 就算 `ink=0` 也还有 0.55 的亮度，"未用"那段会亮成一条完整的线，看起来像水位是满的。两批各自固定 48 个槽位，写不满的用 `scl=0` 清掉。
3. **换屏之后必须 `repaint()`**：`scene.set()` 里的 `slotBegin` 会把整块绘制区清零（槽位是一条共用直线），而 `ParticleText` 有逐字缓存 —— 缓存以为"写过了"，屏幕上就是状态条整行消失，只剩点和水位线（那两个是每帧重写的，所以还在）。

槽位 2200（模型 18 + 数字 13 + 记忆 4 = 35 字 × 58 颗 + 点 14 + 水位 96）。

### 3.1 压缩上下文时，水位线变成"扫带"

`/compact`（或说「压缩一下」）会把更早的对话摘要成一段、替换进上下文。
**屏幕上不动任何内容** —— 压缩是"记得更少但还在聊"，不是换题。只有水位条变：

- 48 颗水位点里有一段 8 颗的亮带，按 `sin(t*2.2)` 在整条上来回扫，颜色转琥珀（`#ffb257`）；
- DOM 那条 `<i>` 加 `.busy`：整条铺满 + `ag-sweep` 1.1s 线性循环（宽度必须 `!important`
  盖掉内联的 `width: pct%`，否则带子被压在很短的一截里）；
- **不画进度条**：摘要要多久取决于模型，进度不可知 —— 画了就是编数字。
  能表达的只有"它在动"。

压缩完成后一次 `usage` 事件把水位数字降下来，带子自动回到静态水位。

### 3.2 两个"整理"指令

| 输入 | 作用 | 屏幕上 |
|---|---|---|
| `/compact`、「压缩一下」 | 摘要更早的对话并替换 | 内容不动，水位带扫一下 |
| `/new`、「开个新会话」 | 上一段压成一条记忆 → 换 sid → 清屏 | 全清（场景、问、答、记录） |

两条都**走旁路，不占模型一轮**，并且进 `↑` 记录（用户能翻回自己下过的指令）。
`/new` 之后首屏**什么都不说** —— 不打"你好，我是…"的招呼。第一个 `session`
事件到达时前端按"断连接 → 换 sid → 清场 → 重连"的顺序做，顺序反了会把旧会话
最后一屏又恢复一遍（resume 是在重连时才来的）。

## 4. 内容区两态

**态 A（无答案）**：场景占满 1360 × 692。输入行以上整个是场景，loading 在正中心。

**态 B（有答案）**：左半答案、右半场景。触发条件是**答案块非空**，不是"答案够不够长"——避免整屏来回跳。

切换走 400ms 横向收展，不做淡入淡出（淡入会让两态短暂重叠）。

## 5. 答案块（左半，668 × 692）

| 项 | 值 |
|---|---|
| 字号 | 20px（`glyphBudget = 90 颗/字`，见 §2.1） |
| 行宽 | 29 字（668 − 左右各 16 边距 = 636，每字占 21.2 = 20 + 一字字距的 0.06） |
| 行高 | 26px |
| 行数 | 14 行（容量 420 字） |
| 每页 | **400 字**（400 × 90 = 36000；14 行 × 30 字 × 90 = 37800 是槽位预留） |
| 顶部 | 问句行：你说的那句，18px 暗色，单行，超出画 `…` |
| 底部 | 页脚：左侧 `1 / 3`，右侧 `空格翻页` |
| 对齐 | **左对齐**，左边距 20px（和问句行同一列） |

分页按 400 字切，不按行数切——按行切会在段落中间断开。

### 5.1 断行：排满，但别把词切开

| 项 | 值 |
|---|---|
| 断行判据 | 宽度（`maxWidth`）**或** 字符数（`maxChars`）先到 |
| 标点回退 | 只回看**最后 6 个字符**，找到句读就退到它后面 |
| 行首禁则 | `。，、；：` 不许落在行首，拉回上一行 |
| 行首禁空格 | 断行落在词间空格上时，那个空格丢掉 |

**回退窗口不能按行长的百分比开。** 以前是 `cur.length × 0.6`：29 字的一行会一路退到第 20 字那个 `、`，**一行白丢 9 个字**——屏幕上 20 字只占 345px，而可用宽度 636px，每行都短一截，66 字的一段话被排成 4 行（2026-10-22 实拍）。标点回退的目的是"别把词从中间切开"，最多管一个词（3~6 字）；"排满"是另一个目标，两者不该互相让路。



**为什么是 400 字而不是更多**：400 字 ×90 = 36000，14 行的预留 37800，剩下 15600 正好够一屏 3 个仪表 + 曲线 + 选项环。再往上加就要从场景里抢。300 字那版试过，一段正常回答就要翻三页 —— 用户读到第一页就没有下文，和"没写完"是同一件事。

**20px 是下限**：再小，`cell` 会掉到 1.5px（点距的物理下限），而 20px 字的笔画只比它细一点 —— 再小就不是"点阵字"而是"点阵噪点"了。

**为什么是 20px 而不是 32px**：可读密度下每个字的点数**与字号无关**（§2.1），32px 一个字也是 90 颗，但一行只放得下 18 字、一页只剩 250 字。同一笔预算下，小字号换更多字，是这一屏唯一正确的取舍。

## 6. 场景区 + 环形选项

### 6.1 几何

| 元素 | 值 |
|---|---|
| 中心 | 态 B：(334, 346)；态 A：(680, 346) —— 都是场景区正中的一半 |
| loading 区 | 场景区左上角 (0, 0)，200 × 88，常驻；表情中心 (52, 44) |
| 主图表区 | 300 × 260 居中（rx 150 / ry 130），仪表 ≤3 |
| 选项轨道 | 正圆 r = 250 |
| 选项标签 | 16px，≤8 字，锚点在轨道外侧 |
| 命中半径 | 70 |

轨道内边缘 240 > 主图对角半径 198，不压主图；轨道外边缘 250 + 标签半宽 64 = 314 < 334，不出界。
loading 区在左上角，选项环正上位在 y = 96，比 loading 区底沿（88）低 8px——刚好让开。这就是它取 200 × 88、而不是"整条顶带"的原因：整条带会和"上"方向抢位置。

**分栏时 loading 区必须跟着场景走**：态 A 它在 (52, 112)，态 B 它在 (784, 112)（732 + 52）。它属于**场景区**，不属于屏幕 —— 不跟着走的话，态 B 下它会被答案块压在字里。

### 6.1.0 仪表标签按**宽度**截断

`fitLabel(text, size, maxW)`：汉字按 `size`、拉丁按 `0.56×size` 累加（再乘 1.06 字距），超了就截断补 `…`。

| 排法 | 标签可用宽度 |
|---|---|
| 竖排（半屏，间距 140） | 120 |
| 横排（间距 110~250） | 96 |

**不能给"字数上限"。** `navidrome` 8 个拉丁字符只占 72px，4 个汉字也才 64px——同一个字数上限对两种文字是两种宽度。按 `max: 4` 给的时候，屏幕上就是 `navi` / `qbit`，用户认不出那是哪个应用（2026-10-22 线上实拍）。

竖排的 120 也不能再大：间距 140，标签超过 140 就会和上下两个仪表的标签贴在一起。

### 6.1.1 主图（仪表）的三种排法

| 条件 | 排法 | 参数 |
|---|---|---|
| 宽屏（场景区 ≥ 820） | 一行横排 | 间距 250，R = 52 |
| 窄屏（态 B，668 宽） | 一列竖排，贴左侧 26% | 步长 140，R = 44 |
| 窄屏 **且有 fork** | **收到环心**，一行横排 | 间距 110，R = 40 |

第三种是被实拍逼出来的：668 宽装不下"一列仪表 + 一个 r=250 的环"。环左边缘在 cx−250，仪表列在 cx−166，仪表整个落在环内，而"过去"那条连线从环心往左拉，**正好横穿圆环中心**（实拍：一条线横着穿过了磁盘表）。有 fork 时主图收到中心，是唯一不重叠的排法。

### 6.2 方位即时间

| 方位 | 起角 | 扇区 | 含义 | 颜色 |
|---|---|---|---|---|
| 右 | 330° | 60°（跨 0°） | **未来**：继续下一步、跑完整流程 | 蓝 |
| 下 | 60° | 60° | **现在**：停下、验证当前、先这样 | 青 |
| 左 | 150° | 60° | **过去**：补细节、还技术债、修老 bug | 橙 |
| 上 | 240° | 60° | **预留**（元操作），本期不实现 | 灰虚线 |

### 6.3 角度公式

同类 n 个，第 i 个（i 从 0 起）：

```
t = 起角 + (i + 0.5) × 60 / n
x = cx + 250 × cos(t)
y = cy + 250 × sin(t)
```

n=1 → 扇区正中；n=2 → ±15°；n=4 → 圆心角 15° / 45° 交替。单类 4 个时两标签垂直间距 29px，标签高 20px——**这是上限**。

### 6.4 上限

| 限制 | 值 | 超出时 |
|---|---|---|
| 总选项 | 8 | 截断，回灌 `dropped` |
| 单类 | 4 | 截断该类，回灌 `dropped` |
| 标签字数 | 8 | 截断加 `…` |
| fork 层数 | 1 | 第二个覆盖第一个（沿用现状） |

**为什么单类 4 个是硬限**：30° 圆心角是"标签不重叠"的下界。若模型给 6 个未来选项，第 5、6 个会在弧上叠字——比截断更糟，因为看起来像界面坏了。

### 6.5 绘制

- 轨道**只画有选项的弧段**，不画整圈（整圈会读成"环菜单"，且多吃 400 颗）。
- 每选项一条从主图边缘到标签的短连线，不画长流光。
- 弧段颜色 = 该类的颜色，亮度统一 0.55；标签颜色比弧段亮一档。

## 7. loading 区：没有 loading 时画小表情

场景区左上角有一块 **200 × 88** 的小区，常驻。它不是主图，也不抢主图——主图仍然在中心 300 × 260。

### 7.1 两态

| 状态 | 内容 | 尺寸 |
|---|---|---|
| 闲置（idle / 输出中） | 小表情 | 48 × 48，用 120 颗 |
| 在想（`thinking`） | 三臂环 + 彗尾 | r = 36，用 260 颗 |

**它不是一个"有 loading 才出现的控件"，而是一个一直在的小东西**：不转的时候有表情，一开口想就收成环。

同一段 260 槽位：表情只用其中 120，其余压暗；转起来时全部聚成三臂。不是"换了一个动画"，是同一批粒子换了个形状。

### 7.2 六种表情

| 表情 | 触发 | 形态 |
|---|---|---|
| 平静 | idle 默认 | 两条短横眼 + 一条平嘴 |
| 眨眼 | 每 4~7 秒，闭 120ms | 眼睛缩成更短的横线 |
| 困 | 超过 90 秒无输入 | 眼睛下垂，嘴平 |
| 在想 | `thinking` | 这一态不是脸，是三臂环 |
| 说话 | 逐字输出时 | 嘴随字开合，眼睛不变 |
| 警觉 | 有告警 / 工具失败 | 眼睛变圆、嘴变小圆，用红 |

### 7.3 规则

- **48px 是下限**：再小，眼睛和嘴的笔画间距会小于 3px，并成一条线。要更大的表情就调大整块，不要只调小字。
- **换表情只在 idle**：8~15 秒一次（平静 ⇄ 困 ⇄ 眨眼）。思考、逐字输出期间锁定，乱换会读成"它不听我说话"。
- 嘴的开合跟**已有打字节奏**同步，不另设节拍器（两份节拍必然漂移）。
- 眼睛 ±2px 微动、整块随相干流场起伏 ±1~2px —— 和骨架同一条规则，**绝不钉死**。
- 加载中**绝不动相干度**（`setCoherence` 会把每颗 UI 点推开约 17px，表情和字一起散成雾）。
- 主图铺开时 loading 区**不动**：它在左上角，和主图、和选项环都不叠加。

## 8. 交互

| 动作 | 结果 |
|---|---|
| 点选项 | **多选一**，点击即发送该选项的 label 作为意图，不需要确认 |
| 空格 / ↓ | 答案下一页 |
| ↑ | 上一页 |
| Esc | 收起 agent（球面 700ms 归位） |
| 输入行回车 | 提交，进入"在想" |

点击即发是"多选一"的定义；复选（勾选 + 确认）不在本期。

## 9. 槽位预算（总 56000）

| 用途 | 槽位 | 说明 |
|---|---|---|
| 答案块 | 37800 | 14 行 × 30 字 × 90 颗（一页 400 字） |
| 场景主图 | 15600 | 仪表 / 曲线 / 乱团 / 选项环 |
| 问句行 | 1800 | 22 字 × 81（18px 可读密度） |
| 输入行光环 | 420 | 椭圆周长 1383px，点距 3.2 |
| loading 区 | 300 | 表情 120 / 三臂环 260（同一段槽位，按态切换） |
| 余量 | 500 | 防止某一层超配时整屏不铺 |

**每层单独 try/catch**：某一层铺不下就丢那一层，不能整屏不铺（踩过）。

场景里的 CJK 标签（`CPU`、`内容`、选项文字）走**可读密度**（§2.1），轴标/单位这类扫一眼就够的走装饰密度。同屏最多三层主图 + 一圈选项，按上面的余量刚好放得下。

## 11. 验收清单

1. 进 agent 后，屏幕上**不出现**桌面球面的经纬弧（背景剩 ≤6%）。
2. 答案块出现时，内容区分成 668 + 24 + 668 两栏，误差 ≤2px。
3. 20px 答案一行 29 字，第 30 字换行。
4. 一页 400 字，超出不截断而是分页，页脚显示 `1 / N` 与「空格翻页」。
5. 给 2 个选项时，两个标签分别在右扇区 ±15°，**不在左侧**。
6. 给 4 个选项且都标 `next` 时，4 个都在右侧，最大圆心角间距 15°。
7. 给 9 个选项时，第 9 个被丢，`dropped` 里有说明。
8. 单个 `past` 选项出现在左侧正中（180°），不在底部。
9. 点任意选项，只发送一次意图，不重复、不需要二次确认。
10. 等待时 loading 区在转、答案区已清空；答完后 loading 区回到小表情。
11. 等待时屏幕上**没有**散开的雾（相干度保持 1）。
12. 收起 agent 后 700ms 内球面完全恢复，无粒子滞留在原位。
13. 不加载时，loading 区里有一个 48 × 48 的表情；不是空框，也不会"加载完就消失"。
14. 开始想的时候，loading 区从表情收成三臂环，**位置不动**，不是"消失后另起一个"。
15. 思考与逐字输出期间表情**不换**；只有 idle 才每 8~15 秒变一次。
16. 眼睛 4~7 秒眨一次，但闭眼时长 120ms——看得见，不会读成"卡了一下"。
17. 状态区一行常驻：模型名、水位条 + `4.2k / 32k`、`16 条`；断线时圆点变红。
18. 分栏后 loading 区在右半场景区左上角（x ≈ 784），**不在答案块里**。
19. 一段 66 字、中英混排的回答，在 636px 宽里排 **3 行**（29/28/23 字），不是 4 行；任何一行都不以空格开头。
20. 仪表标签完整：`navidrome`、`qbittorrent` 全名显示，不被截成 `navi`/`qbitorre`。
21. 输入行外面有一圈流动的粒子（不是一个静态椭圆框）：站在屏幕前不动，8 秒内能看到亮头跑过。
22. 聚焦输入框时那圈变亮，收起 agent 后它随粒子一起收回去。
23. 打 `/compact` 后**屏幕上的内容一个字不动**，只有水位条变成一条来回扫的琥珀带子；完成后水位数字降下来，带子停。
24. 打 `/new` 后场景、问、答、记录全清，**不打任何招呼**；刷新页面回到的仍是这个新会话（不是又随出一个 id）。
25. `/new` 之后再问"上次那个日志"，它能 recall 到上一段（episode 已进记忆）。
26. 回答里**不出现**"第 1 步，调 xxx…"、参数 JSON、代码围栏 —— 那是草稿，出口就切掉。
27. 问"n8n 为什么老重启"时先看 `pods`/`events` 再说话；用户只是问情况时它**不重启**。

## 12. 本期不做（预留）

| 项 | 原因 |
|---|---|
| 上方向（元操作） | 没有确定的内容类型；虚空位比错分类好 |

| 复选 + 确认 | 没有真实用例；先做多选一 |
| 多轮答案并存 | 现在一次只留最新一页 |
| 表情与 persona 情绪联动 | 现在表情只由 busy/thinking/alert 驱动；人格层的"经历过什么"还没有情绪出口 |
