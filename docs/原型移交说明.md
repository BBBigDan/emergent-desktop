## 一、验收结论（可作为基线）

| 项 | 实测值 | 判据 |
| --- | --- | --- |
| 文字可读性 | 骨架偏差 1.1px，槽位 3462 vs 骨架 3500（1:1） | 3× 放大「静默模式」四字一一可辨 |
| 点阵密度 | 点距 4.6px / 光斑 1.42 倍点距（≈30% 暗缝） | 与点阵屏一致，不糊也不断 |
| 门时序 | 收拢 0.7s → 生长 4.6s → 浮现 rev≥0.86 → 散开 1.7s | 逐阶段定格截图核对 |
| 数值稳定 | 半隐式阻尼，坐标不再发散 | 全流程 6.2s 实跑，零 JS 报错 |
| 帧率 | 真机 60fps；无头 SwiftShader 41fps（无毛玻璃）/ 20fps（一层毛玻璃） | 桌面独显/集显均可用，弱机走降级 |

一句话：**视觉与交互层面已可交付，剩下的都是工程接入问题，不是效果问题。**

## 二、代码地图：哪些能直接搬

| 文件 | 职责 | 复用度 | 搬过去要改什么 |
| --- | --- | --- | --- |
| `src/main.js`（~2000 行） | 粒子群 5 形态 + 引力形变 + 呼吸 + 粒子 UI（点阵采样/双层粒子/连线） | **可直接搬** | 只依赖 three，无框架。建议拆成 `createParticleSphere(container, opts)`，把顶部参数块外提为 opts |
| `src/portal.js` | 粒子门：圆角矩形周长参数化 + 环流物理 + 揭示/散开编排 | 逻辑可搬 | 见下节改造点 1、2（iframe → 容器、时间轴 → 状态机） |
| `portal.html` | 页面骨架 + 四层雾化 CSS（`#frost`/`#tint`/`#rim`/`#veil`） | CSS **直接搬** | 只换宿主 DOM，样式规则与 CSS 变量 `--edge/--edge-y/--corner` 原样保留 |
| `vendor/three.module.min.js` | Three.js 本地副本 | 直接搬 | 官方仓库若已有 three，用仓库版本，注意 API 版本差异 |
| `demo-dashboard.html` | 被包裹的测试页 | 弃用 | 换成真实应用窗口/设置面板 |

关键设计资产（比代码更值钱的三条）：

1. **`opacity` 揭示，不用 `scale`/`clip`。** 只有它不碰内容栅格化，字从第一帧就是 1:1 锐利。
2. **画布压在内容之上（`pointer-events:none`）。** 压下面时滞后的粒子会被窗口直接吞掉，边缘只剩空线。
3. **边缘雾化四层分工。** 内容自身 mask（半透明）→ `#frost` 单层 backdrop-filter（毛玻璃）→ `#veil` 全屏雾（浮现期）→ `#tint/#rim`（玻璃厚度）。少任一层都退回「贴了张图」。

## 三、接入官方仓库要改的三个点

### 1. iframe → 同文档容器（工作量最大的一处）

现状：`layout()` 用视口算 `rw/rh`，`frame.src` 指向演示页，粒子几何以屏幕中心为原点。

改造：

- 容器改成一个普通 `div`（或路由 outlet），`layout()` 改用 `getBoundingClientRect()` 取 `rw/rh/cx/cy`；
  粒子几何仍然只需要「中心 + 半宽 + 半高」，物理代码一行不用改。
- 内容不再需要 iframe 的**半透明 mask 来「透出背后」**：同文档后，`#frost` 的 backdrop 采样源就是真实背景，
  雾化会自然得多。但边缘 mask 建议保留（比硬边柔和），只是 alpha 可以从 0.40 提到 0.6 左右。
- 同文档后跨域限制消失：窗口内也能拿到鼠标事件，粒子扰动不需要再区分「窗内窗外」。

### 2. 时间轴 → 状态机

现状：`portal.js` 自带 `SEED_MS / GROW_MS / REVEAL_A / SCATTER_*` 和全局 `now`，独立页面自驱动。

改造：暴露成组件 API，内部保留同一套时间轴——

```
idle → seeding → growing → revealing → revealed
                                    ↘ dismissing → idle
```

- `open(target)` / `close()`：替代现在的 `replay()` / `collapse()`（`window.PORTAL` 已经预留了这两个入口，包一层即可）。
- 回调：`onRevealed` / `onDismissed`，供路由切换、埋点、焦点管理使用。
- 打开过程中若用户再次触发，要能「从当前 pe 继续」而不是重置（现状 `replay()` 会硬回 0，接入时必须改成可打断）。

### 3. 性能预算与降级链

- 桌面：9000 粒 + 一层毛玻璃，目标 60fps。
- 集显 / 高 DPI 手机：粒子 3000–4000，毛玻璃关掉（`?frost=0` 的等价开关），保留半透明 + 暗角。
- 判定方式：启动时测 3 秒平均帧时，低于 45fps 自动降一档（不要靠 UA 猜）。
- 注意：**`backdrop-filter` 的成本在采样与合成，不在半径**（20px→15px 实测无改善），降半径没用，只能减层或关掉。

## 四、风险清单

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 雾化吃掉边缘内容 | 窗口页头/页脚只有 40–56px，横纵同宽会把标题削掉 | 纵向雾带取横向的 0.72（已实现）；真实页面内容留 ~70px 安全边 |
| 两个独立 rAF / 两套 renderer | 主页面 + 粒子门同屏时双倍开销 | 接入时合并为单 renderer 单循环，粒子门作为其中一个 scene 层 |
| 长时间环流 | `uPar` 单调增长，理论上精度会耗尽 | double 下可跑数天；若改成 GPU instanced 必须取模 |
| 移动端触摸 | 鼠标扰动逻辑不覆盖 touch | 补 `pointerdown/move`，或直接禁用扰动 |
| 字体可用性 | 等线 Light 是 Windows 字体，Linux/网页端没有 | 接入时换开源瘦字（思源黑体 Light / Inter Light），**必须重跑点阵探针**：笔画需 ≤1 格，否则重回「糊」 |

## 五、下一阶段顺序（建议）

1. **同步官方仓库，先读结构**：确认前端栈与版本（Next.js？组件库？构建链），找到「窗口/面板出现」这件事目前在哪实现。不要先动代码。
2. **单点替换**：只把某个窗口的出现动画换成粒子门，粒子层用独立 canvas 覆盖，其余交互不碰。验证同文档下的雾化与性能。
3. **接入全局状态**：状态机 + 打开/关闭回调，处理路由切换时「窗口还没淡出就被卸载」的情况。
4. **再往外扩**：粒子 UI（`main.js`）替换设置面板里的按钮/输入框，这一步才是「涌现式 UI」的真正落地，比门更重要也更难。
5. **字体与可读性复测**：换字体后必须重跑 `.tmp/fontprobe.html` 与 `?selftest=1`，不要凭截图目测。

## 六、调试入口（搬走前先熟悉）

| 入口 | 作用 |
| --- | --- |
| `?at=1.6&freeze=1` | 同步预热到 1.6s 并定格，无头截图可复现任意时刻 |
| `?n=3000` | 粒子数，压测/弱机用 |
| `?frost=0` | 关毛玻璃，只剩半透明 + 暗角 |
| `?selftest=1` | 同步跑物理循环出数值面板（骨架偏差/槽位/角色分布） |
| `window.PORTAL.dump(n)` | 抽样导出粒子位置/目标/透明度/类别，排查「粒子没渲染」类问题 |
| `crop.html?src=&x=&y=&w=&h=&s=` | 截图放大，看边缘与字 |
