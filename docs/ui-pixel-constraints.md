# 粒子 UI 的像素级硬约束

> 这些数字都是**在真屏幕上量出来的**，不是估算。改渲染/排版之前先读一遍，
> 每一条都对应过一次"看着就是不对，但说不出哪里不对"。
> 从 `.workbuddy/memory/MEMORY.md` 迁出（那边只留索引）。

## 点大小与像素

- `gl_PointSize = size × (屏高/2) / 距机位` —— **不含 fov 修正**，实际像素直径约为推算值的一半；
  叠加柔光晕后可见芯 ≈ 标称值的 **0.43**。必须按**屏幕实测芯径**反推。
- 换算走 `spotUI(s) = s·tan(fov/2)/UI_S`（按世界尺寸直推会 2 倍偏大）。正确值 2.46÷2.5 = **0.86 相切**。
- 点距 / 可见芯径：**>1.5 显"断"，≈1 相切，<0.8 过曝**。目标点格心对齐、无抖动；但**粒子本身不能钉死**。
- 点径要跟字号走，但**不能按比例**：`size×0.075` 在 18px 上只有 1.35，笔画 1.1px 落在 1.8px 点格上
  被切成两条平行点列（屏幕上像每个字被描了边）。用 `1.0 + size×0.045`（16→1.72 / 18→1.81 / 32→2.44）。

## 动起来才算活着

- **"看起来不会动"的判据**：周期 >5s 当静止；幅度 <1px 无效。测**每秒累计路程**（10~15 px/s），
  不测净位移（来回晃也能是静止）。
- 骨架由**相干流场**（fbm 按屏幕坐标采样）推着起伏 ±1~2px，弹簧略欠阻尼。
  **绝不能写"距目标 <x 归零"的弹簧死区**（一到位就锁死 = 贴图）。
- 悬停"更清楚"要**增援粒子真的进细网格槽位**（密度 ≥ 骨架 2 倍）+ 公转光尘。骨架与增援必须是**不同网格**。
- **"不规整" = 四层叠加**：过采样 1.3x、逐粒子点径/亮度差异、加色混合（alpha 0.5~0.8）、
  连线层（线条 1.75 格、文字绝不连）。点阵画线笔画宽 ≥ cell × 0.40，否则断虚线。

## 字能不能读

- **只看"笔画 ÷ 点距"，不看字号**：每字 40 颗时 cell 2.55、20px 的笔画 1.3px、比值 0.51 →
  整行碎成渣（像每个字被描了两遍边）；**90 颗 → cell 1.70 才读得出**。
- **每字点数与字号无关**（cell 与笔画同步放大），"换大字号省槽位"不成立。
  所以 `glyphBudget(size, read)` 两档：`read` 时 `size×4.5`；池子 `UI_POOL=56000`
  （答案 32400 + 问 1782 + 表情 300，余给场景）。
- **13px 是粒子字的下限**（汉字在 13px 必糊：cell 1.7 / 笔画 0.9，整行只留一个汉字）。
- 32~35px 配 cell 1.9。CJK 可读性看笔画÷点距 ≈0.8 格（雅黑 400 = 1.2 格填死；等线 Light 0.8 最好但 30px 会碎）。
  汉字加一格字距，**文字不加描边**。

## 排版

- **字距 0.06em 必须两处同源**（`ParticleText.spacing` 与 `answer.js` 的 `widthOf`）；
  **行首禁则**回拉标点 → `max` 要给 `maxChars+1`；**槽位按 max 预留**，行数×字宽一变
  `ANS_SLOTS` 就得跟着变，否则末尾 `base=-1` 静默丢句。
- **断行回退窗口不能按行长百分比**：`cur.length×0.6` 会让 29 字的一行退到第 20 字（`、`），
  **一行白丢 9 字**（屏幕每行只占 636px 中的 345px，一段话被排成 4 行 = "没写完"）。
  窗口只看最后 6 字符；**行首禁空格的判断必须放在断行之后**（断行就发生在处理那个空格那一轮）。
- **点阵标签按宽度不按字数**：`max: 4` 对汉字 64px、对拉丁 36px → `navidrome` 变 `navi`。
  `fitLabel(text, size, maxW)`：汉字 size、拉丁 0.56×size、×1.06 字距。
- **"只看到一行"的两处根因**：① `rawSpeech` 的 `.split('\n').filter(Boolean)[0]` 只留第一行；
  ② **工具 schema 的 description** 写着 `≤20 字，例如 "CPU 3% · 内存 62%"` —— 权重高于提示词表格，
  只改提示词没用。读数是仪表的活，`reading` 必须是 2~5 句的判断。
- **`rawSpeech.slice(0, 40)` 曾把回答切成半句话**（"一行 20 格"时代的常量，答案块到 400 字/页后必须一起改）；
  `MODEL_MAX_TOKENS` 2000 对 1200 字中文太紧。

## 槽位分配

- 总量 6400 四家分：**问 792（先分配）** + 答（big 3600 / compact 1900）+ 转圈环 220 + 场景。
  场景（3 仪表 + 乱团 + 分叉）实测要吃 **3140~3490**，多给答案 300 就会把分叉第二个分支挤成 `dead`。
  场景里 `alloc()` 抛异常会让**整屏不铺**，每层单独 try/catch。
- **`slotPut` 的 scl 是整批一个**，`ink=0` 也有 0.55 亮度 → 水位线的已用/未用必须分两批写。
  换屏后 `ParticleText` 缓存挡不住 `slotBegin` 清零，要显式 `repaint()`（`force:true`）。
- **分栏必须"先切 area 再铺"**：铺完再收缩时第二次 `set` 申请不到槽位（allocator 已被第一次占满），
  场上永远停在满宽那版。`areaB` 是场的位置，答案永远在左半 `a.x+20`。
- **`scene.step()` 全工程没人调用**（曾经）：相变（溶解）时钟只在 `this.tr` 里，没人推进，
  "清场"永远停第一步。现在由 deskagent 的 `tick()` 驱动。**任何 `tr` / `step` 型状态机都要先确认有人调 step。**
- **`ParticleText` 的逐字缓存必须比 `(ch,x,y)`**：只比 ch/x 时整行上下挪动会被判"没变"，
  旧字留原地、新字不画。重建块前还要 `clear()` 掉旧块的 typing interval（它继续往同一段槽号写旧坐标）。

## 亮度与材质

- **`ink` 拉不开对比**（alpha = 0.55+0.45×ink，只差 1.8 倍）→ 流动只能靠**点径**：另开一批更大点径的流光。
- **看不见 = 挪出屏幕**（`ink:0` 仍有 55% 亮度）。收起后残留两串大点，踩过。
- **背景压暗是"压暗比例"**：`drawDim` 越大越暗（0.84 剩 16%，0.94 剩 6%）。写成 0.30 反而把背景提亮到 70%。
- **加载中绝不能动相干度**：`setCoherence(0.58)` 把每颗 UI 点推开 ~17px，字/仪表/曲线一起散成雾 ——
  这是"有粒子云时什么都看不出来"的根因。相干度只属于相变（溶解）。
  状态靠颜色+形状+背景亮度分：在想 = 青色三臂环 + 空屏背景 38%（有内容只 18%），输出 = 白字 + 背景 6%。
- **有场景时不转圈**：环会压住分叉连线。
- **输入行光环**（`halo.js`）：均匀亮度的闭合环会被读成"边框"，必须靠三处流动亮头存在；
  椭圆按**弧长**均分（按角度会让长轴两端挤三倍密度）。

## 渲染细节

- **预乘 alpha 陷阱**：`vec4(rgb,1.0)` + Additive 在黑底 OK，叠在亮内容上会变黑点。
  正解 `float a = core*vA; vec4(color*a, a)` + NormalBlending。
- canvas 是替换元素：`inset:0` 不拉伸，必须显式 `width/height:100%`。
- **"参数说了 A、实际是 B"先加调试双字段**（外面算的 geom vs 里面记的值）。看截图永远查不出来。
- **rAF 回调里的异常是静默的**（整条链断掉、控制台无输出），一律包 try。
- **官方 app 图标不能直接降采样**（满幅插画降到 20×20 = 实心方块）；按题材重画字形，取官方主色。
  52px ≈ 28 格才认得出。
- 局部预览别用 `python -m http.server`（不发 Cache-Control，Chrome 会启发式缓存 ES Module）
  → `node auth/serve.mjs <port> [root]`。

## 定位与构图

- **思考过程面板**：内容区左上 `x+116`、`470x250`；**小脸锚内容区不锚 area** ——
  锚 area 的话分栏后它跳到右半，那一栏跟着跳正好盖住新铺的仪表。
- 面板开着时答案 `centerY += 92`，正好落在框底之下；用 `ans.layout()` 只重绘不重打。
- **半宽 668 的两处必然冲突**：竖排仪表步长只能 140（168 时第三个圆环压曲线）；
  **有 fork 时主图必须收到环心**（一列仪表与 r=250 的环相交，连线横穿圆环）。
- **点阵尺度不能按官方卡片复刻**（262px 卡塞进点阵只有 16 格/字）。原型 CELL 2.5 + 上屏 2.25~2.59 倍。
- **问和答必须是两块字**：输入回显只进输入行（18px 暗色），回答进上面大块（32/22px 亮色）。
  写进同一块 → 打字时长在回答区、提交后两句叠在一起。
- **状态区是 DOM**（11px 汉字点阵必糊：格距下限 1.5px > 笔画 0.8px），模型名 / 水位条 / 记忆条数常驻，细账进 tooltip。
